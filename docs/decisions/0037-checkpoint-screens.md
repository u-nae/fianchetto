# 0037 체크포인트 화면: 위 라벨 저장 시트, 이력 탭의 체크포인트 행, 과거 구성 띠 아래 패널

- 상태: 확정 (사용자 선택, 디자인 세션 시안)
- 날짜: 2026-10-19 (시안 선택 2026-10-15)

## 맥락
W22는 고정한 revision에 제목·진행 메모·다음 할 일을 담은 불변 체크포인트를 저장하고 조회한다(PRD §6-G, A10). 저장은 현재 구성에서만
하고, 시트가 열린 동안 구성 편집을 막는다. 조회는 연결된 구성을 읽기 전용으로 보여 주며 복원은 별도 동작이다. 보관된 Board에서는
저장을 거부한다(0009). 화면에서 정할 것은 세 가지였다. 저장 시트의 배치, 이력 탭에서 체크포인트를 보여 주는 방식, 체크포인트를 골랐을 때
내용을 놓는 자리다. 16.2는 revision 행 오른쪽에 체크포인트 수(`flag` + 숫자)를 두기로 미리 적어 두었다.

## 결정
디자인 세션이 실제 SwiftUI 컨트롤로 시안을 렌더링했고(라이트·다크), 사용자가 셋 모두 권장안을 골랐다.
- 저장 시트는 위 라벨형(폭 480)이다. 제목·진행 메모·다음 할 일을 라벨 아래 칸에 두고, 부제에 열 때 고정한 revision을 적는다.
  저장 뒤 고칠 수 없다는 안내를 두고, 실패하면 입력을 유지한 채 버튼 위에 안내한다. 다음 할 일은 목록이 아닌 여러 줄 텍스트다.
- 이력 탭에는 체크포인트마다 행 하나를 둔다. revision 행 순번 역순은 그대로 두고, 체크포인트 행은 기록 시각이 저장 시각 이하인 첫 revision 행
  앞에 끼운다. 행의 표시는 `flag.fill`, 제목, '체크포인트 · #n · 시각'이다. 16.2의 'revision 행 오른쪽 체크포인트 수'는 두지 않는다.
- 체크포인트를 고르면 #n을 고른 것과 같은 과거 구성 보기가 되고, 과거 구성 띠 바로 아래에 접을 수 있는 체크포인트 패널이 붙는다.
  패널은 진행 메모와 다음 할 일을 두 열로 보여 준다. 체크포인트가 현재 revision에 붙어 있어도 같다(편집 가능한 현재 구성 위에 패널을 얹지 않는다).
- 진입점은 파일 메뉴 '체크포인트 저장…'(단축키 없음)과 구성 열 툴바의 `flag` 버튼이다.

## 대안
- 묶음 양식(grouped Form) 시트: 시스템 설정과 닮았지만 앱의 다른 시트와 모양이 달라지고 세로가 가장 길다.
- 왼쪽 라벨(columns) 시트: 세로는 짧지만 메모 칸이 라벨 열만큼 좁아진다.
- revision 행에 개수만 표시: 목록은 짧지만 제목으로 체크포인트를 찾을 수 없고, 다시 이어 갈 맥락이 한 번 더 고른 뒤에야 보인다.
- 인스펙터 아래 카드: 기존 구조와 가장 가깝지만 폭 300에서 긴 메모는 스크롤해야 하고, '고른 항목' 카드와 자리를 다툰다.
- ⌘S 단축키: 빠르지만 습관적으로 누를 때마다 시트가 뜬다. 복원(0035)처럼 단축키를 두지 않는다.

## 영향
- DESIGN.md 16.2(체크포인트 행, 체크포인트 수 표시 삭제), 16.6(저장 시트·패널·진입점), 16.5(제안 식별자), 11.1(파일 메뉴·툴바), 5.1(기호)을 고친다.
- 접힘 상태는 화면 상태라 저장하지 않고 revision도 만들지 않는다. 다른 체크포인트를 고르면 펴진 상태로 시작하고, 비교 중에는 패널을 그리지 않는다
  (W22 명세 게이트 t-w22-72ee8b76의 보조 규칙).
- W23 이미지 첨부는 저장 시트의 '다음 할 일' 아래와 패널 아래 줄에 더한다. W22에서는 꺼진 자리를 미리 두지 않는다.
- 저장 실패 줄(기호 + 긴 문구)은 W07·W21 시트의 빨간 한 줄과 모양이 다르다. 사용자가 시안을 보고 고른 것이고, 통일 여부는 전체 다듬기 때 본다.
