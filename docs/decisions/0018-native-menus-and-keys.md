# 0018 메뉴 꺼짐, 오른쪽 클릭 메뉴, Delete 키, 드래그 강조

- 상태: 확정 (사용자 승인, 디자인 세션 권장안)
- 날짜: 2026-10-03

## 맥락
네이티브 동작 점검(`docs/design/AUDIT-2026-10-03.md`)에서 세 가지 문제가 나왔다.
- 메뉴 항목이 상태와 관계없이 늘 켜져 있었다.
- 오른쪽 클릭 메뉴에는 '열기'와 'Finder에서 보기'만 있었다.
- Delete 키는 아무 일도 하지 않았고, 드래그할 때 놓을 위치가 표시되지 않았다. 도움말 메뉴는 내용 없이 켜져 있었다.

메뉴를 늘 켜 둔 이유는 W07에서 겪은 문제 때문이다. SwiftUI가 메뉴 항목의 꺼짐을 메뉴를 열 때까지 갱신하지 않아, 꺼짐이 굳으면
단축키가 동작하지 않았다. 앱 이름에는 원본을 지운다는 인상을 주는 표현('삭제')을 쓰지 않는다(CLAUDE.md UI·문구).

## 결정
- 메뉴: 'Board 만들기…'(⌘N)를 뺀 모든 명령을 모델의 `can…` 값으로 끈다(판단 값은 기능 세션이 추가).
  - ⌘N만 늘 켜 두는 이유: 앱 시작 때 저장소를 여는 동안 꺼짐이 굳으면, 메뉴를 열기 전까지 ⌘N이 동작하지 않았다(W07).
  - 다른 항목은 확인을 거쳐 함께 끈다. 앱 시작 직후 파일 메뉴를 열어 꺼진 상태를 만든 뒤, 선택을 바꾸고 메뉴를 열지 않은 채
    단축키(⌘⌫)를 눌러도 동작했다. 선택 변화에 따른 꺼짐은 바로 반영된다. 이 순서는 `NativeCommandUITests`에 회귀 테스트로 남긴다.
- 오른쪽 클릭 메뉴: 항목 종류별로 메뉴 막대 명령의 일부를 같은 이름과 같은 순서로 보여 준다. Board 행에도 오른쪽 클릭 메뉴를 둔다(DESIGN.md 11.1).
- Delete 키: 트리에서 `onDeleteCommand`로 '제거…' 확인 창을 연다. 편집 메뉴의 시스템 '삭제' 항목 이름은 그대로 둔다(사용자 결정).
- 드래그: 놓을 수 있는 Wing 행과 빈 영역만 시스템 강조 색 테두리로 표시한다.
- 툴바: 구성 열에 'Bishop 추가'와 'Wing 추가'를 둔다.
- 도움말 메뉴: 기본 항목을 뺀다.

## 대안
- 메뉴를 늘 켜 둔다(이전 방식): 실행할 수 없는 명령이 켜진 채 보이고, 눌러도 아무 일도 일어나지 않는다.
- 단축키가 없는 항목만 끈다: 확인해 보니 고착은 시작 시점의 ⌘N에만 해당해서, 이렇게 나눌 필요가 없었다.
- Delete 키를 `onKeyPress`로 받는다: '삭제' 항목은 켜지지 않지만, 목록의 키보드 포커스를 가져가 방향키와 펼치기·접기까지 막는다.
  사용자가 실제 키보드로 확인했다.
- 시스템 '삭제' 항목 이름을 AppKit으로 '제거'로 바꾼다: SwiftUI가 메뉴를 다시 만들면 이름이 돌아올 수 있고, '제거…'와 비슷한 항목이 두 개가 된다.
- Delete 키를 지원하지 않는다: Mac 목록의 관례(Delete로 지우기)를 따르지 않게 된다.

## 영향
- 검증: XCUITest에서는 트리 목록이 키보드 포커스를 받지 못한다. 그래서 방향키·펼치기·Delete 키는 2026-10-03에 사용자가
  실제 키보드로 수동 확인한 것으로 대신하고, 메뉴 꺼짐과 단축키는 `NativeCommandUITests`로 확인한다.
- 오른쪽 클릭 메뉴의 편집 명령과 툴바 버튼은 Board를 편집할 수 없을 때(보관된 Board) 꺼진다.
- 단일 창(`Window`) 전환(점검 7번)은 이 결정에 포함하지 않는다. 따로 진행한다.
