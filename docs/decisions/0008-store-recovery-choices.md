# 0008 저장소를 열 수 없을 때의 복구 선택지: 다시 시도·Finder에서 보기·종료

- 상태: 확정 (명세 게이트 t-w07-6c0016f4, Q-W07-1)
- 날짜: 2026-10-02

## 맥락
PRD §7은 저장소를 열 수 없을 때 "오류와 복구 선택지를 제공"하고 새 빈 DB로 조용히 교체하지 말라고만 하고, 선택지의 내용은 정하지 않았다.
앱이 사용자 데이터 파일을 옮기거나 새 저장소를 만드는지가 선택지에 따라 달라진다. 근거: docs/PRD.md#7-기록-정책과-저장-안정성.

## 결정
선택지는 "다시 시도", "저장소 위치를 Finder에서 보기", "종료" 세 가지다. 앱은 기존 저장소 파일을 옮기거나 새 저장소를 만들지 않는다.
원인(손상·호환 안 됨·권한 없음·기타, W04 범주)은 안내 문구로 알린다. 사용자가 직접 파일을 옮긴 뒤 다시 시도하면 새 저장소가 생긴다.
에이전트 권장안: A (채택 여부: 채택).

## 대안
- 보관 후 새로 시작도 제공: 앱이 기존 파일 묶음을 날짜 붙은 보관 폴더로 옮기고(삭제 없음) 빈 저장소를 만든다. 앱이 사용자 데이터 파일을 옮기는 코드와
  부분 이동 실패 처리가 늘어난다.
- 손상일 때만 보관 후 새로 시작: damaged에만 위 동작을 주고 incompatible은 업데이트 필요, accessDenied는 권한 확인을 안내한다. 원인별 분기가 늘어난다.
