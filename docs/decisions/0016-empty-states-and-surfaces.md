# 0016 빈 화면은 두 색 체스판, 면 색·Board 제목 머리·세리프는 쓰지 않는다

- 상태: 확정 (사용자 선택, 디자인 세션 시안 수정안)
- 날짜: 2026-10-02

## 맥락
DESIGN.md 15장에 세 항목이 남아 있었다. `ThemeSurface`를 어디에 쓸지, Board 제목에 세리프를 쓸지, 빈 화면 일러스트를 쓸지다.
지금 앱에는 Board 제목 머리가 없어서, 이걸 넣으면 새 화면 요소가 생긴다.

## 결정
디자인 세션이 실제 SwiftUI 컨트롤로 시안을 렌더링했다. 빈 화면 세 가지와 구성 화면 세 가지를 라이트와 다크로 보여 줬고,
사용자가 아래처럼 정했다.

- 빈 화면: 'Board가 없습니다'와 '구성이 비어 있습니다'의 기호 자리에 4×4 체스판 일러스트를 둔다. 실제 체스판처럼 밝은 칸과
  어두운 칸 두 색만 쓴다. 밝은 칸은 `ThemeLine`, 어두운 칸은 `AccentColor`이다. 미트라, 녹색, 바탕 면 색은 넣지 않는다.
- 글꼴: 시스템 서체를 그대로 쓴다. SF Rounded는 한글이 바뀌지 않아 효과가 없었고, New York(세리프)은 한글이 명조 계열로 대체된다.
- 구성 화면: 지금 모습을 유지한다. Board 제목 머리를 두지 않고, 상세 영역 바탕도 시스템 그대로 둔다.
- 일러스트는 벡터 자산 대신 SwiftUI 코드(`Features/Shared/ChessboardIllustration.swift`)로 그린다. VoiceOver에서는 숨긴다.

## 대안
- 체스판 모서리와 미트라, 녹색 대각선 칸, 세리프 제목, `ThemeSurface` 바탕: 정체성은 가장 강하지만 사용자가 더 단순한 형태를 골랐다.
- 미트라와 세리프 제목만: 테마가 약하고, 한글 세리프 대체 글꼴이 시스템 UI와 어울리지 않는다.
- Board 제목 머리(세리프), 상세 영역 `ThemeSurface`: 새 화면 요소가 생기고, 오래 읽는 영역은 조용하게 둔다는 원칙(DESIGN.md 1장)과 맞지 않는다.
- PDF·SVG 일러스트 자산: 라이트·다크·고대비 변형을 따로 만들어야 한다. 코드로 그리면 색 토큰의 변형을 그대로 쓴다.

## 영향
- `ThemeSurface`와 `ThemeBoardGreen`은 지금 어느 화면에서도 쓰지 않는다. 앱 아이콘(0014)과 팔레트 기록(0011)에 맞춰 토큰은 그대로 둔다.
- 오류·안내 빈 화면('현재 구성을 읽지 못했습니다', '항목을 고르세요', 복구 화면)은 시스템 기호를 유지한다.
- 문구, 접근성 식별자, 화면 상태 모델은 바뀌지 않는다. 빈 구성 화면의 드롭 처리(`dropDestination`)도 그대로 둔다.
- 체스판 밝은 칸(`ThemeLine`)은 장식이라 대비 요구가 없다. 고대비에서는 토큰의 고대비 값으로 대비가 높아진다.
