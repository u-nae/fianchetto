# 0019 이력 화면: 오른쪽 열의 '항목 | 이력' 탭과 제자리 과거 구성

- 상태: 확정 (사용자 선택 A안, 오른쪽 열 하나로 합치는 수정은 기능 세션·디자인 세션 공동 권장)
- 날짜: 2026-10-03

## 맥락
W17(이력 목록·날짜 조회)과 W18(과거 구성 읽기 전용 보기)에 앞서 화면 구조를 정해야 했다. PRD §6은 기본 창 가운데에 현재 또는 과거
구성 트리를 두고, 이력 모드에 기록 시각과 '과거 구성 · 읽기 전용'을 표시하도록 했다. 같은 시기에 사용자가 "트리 열이 좁다"는 의견을 냈다.

## 결정
디자인 세션이 실제 SwiftUI 컨트롤로 세 가지 구조를 렌더링해 보여 줬다. A는 오른쪽 이력 패널, B는 구성 열 전환, C는 별도 이력 창이다.
사용자가 A를 골랐다. 그 뒤 오른쪽 열이 둘이 되지 않도록 다음처럼 다듬었다(DESIGN.md 16장).
- 오른쪽 열은 인스펙터 하나다(⌥⌘I로 접고 편다). 그 안의 '항목 | 이력' 세그먼트로 상세와 이력을 전환한다. 이력 탭을 열면 Board 사이드바를 접는다.
- revision을 고르면 가운데 영역이 그 자리에서 과거 구성으로 바뀌고, 위에 과거 구성 띠가 붙는다.
- 과거 항목의 당시 경로와 현재 위치는 이력 탭 아래쪽의 '고른 항목' 카드에 둔다.
- revision 행은 `RevisionSummary`(순번·시각·원인)만 쓰고, 원인 문구 표는 DESIGN.md 16.2를 따른다. 차이 요약은 행에 붙이지 않는다.
- 이력 보기 단축키는 ⌘Y다.

## 대안
- B 구성 열 전환: 열 개수는 그대로지만 같은 열의 의미가 바뀌고, 과거 트리와 항목 정보가 오른쪽 한 열을 나눠 쓴다.
- C 별도 이력 창: 헷갈림이 가장 적지만 창이 둘이 되고, PRD의 기본 창 구성과 달라진다.
- A를 그대로(이력 패널과 상세 영역이 따로): 오른쪽 열이 둘이 되어 가운데가 더 좁아진다.
- 행마다 차이 요약 표시: 행마다 스냅샷 두 개를 디코딩해야 해서, W17의 "고른 revision만 디코딩" 원칙과 맞지 않는다.

## 영향
- 구현(화면 상태 모델·서비스·View)은 기능 세션이 W17·W18에서 이 명세를 보고 진행한다.
- 사용자가 상세 영역을 인스펙터로 바꾸기로 했다(기능 세션이 진행). '항목 | 이력' 세그먼트는 W17에서 그 인스펙터 안에 얹는다.
  아이콘 보기(W28, 0020)도 W17보다 먼저 들어오며, 과거 모드는 두 보기에서 같은 띠와 같은 읽기 전용 규칙을 따른다.
- 체크포인트 깃발은 자리만 정하고, 표시는 W22에서 한다.
- 보관된 Board는 이력 조회·비교·새 Board 만들기만 되고, 복원은 막는다.
