# 0036 과거 구성으로 만든 새 Board는 원본과 참조 레코드를 공유한다

- 상태: 확정 (명세 게이트 t-w21-bcfe30da, Q-W21-1)
- 날짜: 2026-10-15

## 맥락
PRD §6-F는 새 프로젝트의 "연결 참조는 같은 로컬 대상과 접근 정보를 사용할 수 있다"고만 한다. 원본 revision이 기록한 ResourceReference
레코드를 새 Board의 Node가 그대로 가리킬지(공유), 같은 북마크 데이터로 새 참조 레코드를 만들어 가리킬지(복제)를 정하지 않았다.
참조 레코드의 북마크·마지막 해석 경로는 운영 정보라 revision과 분리되어 갱신되므로(0003, 0007, 불변식 8), 공유하면 한쪽 Board에서 한
접근 정보 갱신(stale 북마크 갱신, 권한 복구)이 다른 Board에서도 보이고, 복제하면 Board마다 따로 복구해야 한다. 대상 교체는 어느 쪽이든
새 참조를 만들므로(불변식 3) 상대 Board에 영향이 없다. 근거: docs/PRD.md#f-복원과-새-프로젝트-만들기, docs/PRD.md#5-핵심-개념과-데이터-규칙,
0003, 0007.

## 결정
새 Board의 Node는 원본 revision이 기록한 참조 ID를 그대로 쓰고 새 참조 레코드를 만들지 않는다. W20 복원이 기록된 참조를 그대로 쓰는 것과
같다. 한쪽 Board에서 같은 대상의 접근 정보를 복구하면 다른 쪽도 함께 복구된다(같은 실제 대상). 대상 교체는 새 참조라 상대 Board를 바꾸지 않는다.
에이전트 권장안: A (채택 여부: 채택)

비평 보충: 이 결정으로 한 참조 레코드를 두 Project가 처음으로 함께 참조한다. 내보내기(W24)가 Project 단위로 참조를 모으면 같은 레코드를
Board마다 내보내지만 가져오기는 새 ID를 만들므로 왕복에 문제가 없다. 활성 Board에서 한 접근 복구가 보관된 원본 Board의 레코드도 갱신하는데
0012가 보관된 Board의 접근 정보 갱신을 이미 허용한다.

## 대안
- 같은 북마크로 새 참조 레코드 복제: 원본 참조의 북마크 데이터·최초 경로·종류를 복사한 새 참조 레코드를 만들고 Node의 참조 ID도 새 값으로
  재매핑한다. 두 Board의 접근 정보가 완전히 독립된다. 비용: Domain 재매핑이 참조 ID까지 다루고 서비스가 참조 레코드를 읽어 복제하며, 참조 레코드
  수가 늘고, stale 북마크를 Board마다 따로 다시 선택해야 하며(0012), 내보내기(W24)에 같은 대상의 참조가 중복된다. 되돌리려면 데이터 이전이 필요하다.

## 영향
- W21: obligation W21-shares-reference-records, W21-shared-access-info, W21-replace-target-independent, W21-copies-unreachable-items,
  W21-remap-preserves-structure, W21-service-atomic-commit. 만들기는 참조 레코드를 읽지 않으므로 결정표 duplicate_request_outcome에 참조
  읽기 실패 입력이 없다.
- W24 내보내기: 여러 Board가 같은 참조 레코드를 쓸 수 있음을 전제로 참조를 모은다.
- PRD·TECH_STACK 본문은 바꾸지 않는다(§6-F "사용할 수 있다"의 해석).
