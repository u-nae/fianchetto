# 0022 아이콘 보기 타일과 Bishop 용도 배지의 시각 규칙

- 상태: 확정 (사용자 선택, 디자인 세션 시안)
- 날짜: 2026-10-03

## 맥락
사용자가 아이콘 보기(W28, 0020)와 Bishop 용도 아이콘(W29, 0021)을 첫 버전에 넣기로 했다. 디자인 세션이 실제 SwiftUI 컨트롤로
타일 두 안(기호 타일, 파일 종류 아이콘 + 배지)과 용도 배지 시안을 렌더링해 보여 줬다. 기능 세션은 실제 대상 파일의 아이콘을
쓰면 대상 접근이 늘어나 경량화 원칙(PRD §8)에 어긋난다고 짚었다.

## 결정
- 타일 기본값은 기호 타일이다. 목록과 같은 기호를 크게 쓴다(DESIGN.md 17.3). 앱의 정체성(미트라)을 기본으로 보여 주기 위해서다.
- 설정에 'Bishop 아이콘: 기호(기본) | 파일 종류 아이콘'을 둔다. 파일 종류 아이콘은 기록된 경로의 확장자로 정한 macOS 일반 아이콘에
  작은 Bishop 배지를 붙인다. 디스크에 접근하지 않는다. 화면 설정이라 revision을 만들지 않고, 두 보기에 함께 적용한다(18.5).
- Bishop 용도 배지는 8종(문서, 데이터, 이미지, 코드, 참고, 발표, 할 일, 디자인)과 기본(배지 없음)이다. 저장 키와 기호는 18.2 표를 따른다.
- 합성: Bishop 심볼 오른쪽 아래에 SF Symbol 배지를 겹치고, 배지 둘레만큼 오려 낸다(compositingGroup + destinationOut).
- 폴더 Bishop(F1): 용도 배지가 폴더 배지 자리를 대신하고, 폴더라는 사실은 종류 문구 'Bishop · 폴더'로 알린다.
- '파일 종류 아이콘' 모드에서는 용도 배지를 아이콘에 그리지 않고, 인스펙터와 VoiceOver 라벨에서 보여 준다.
- 아이콘 보기의 격자, 선택, 드롭, 상태 배지, 경로 막대, 빈 Wing, 탐색 키(⌘1/⌘2, ⌘↓/⌘↑, ⌘[)는 DESIGN.md 17장을 따른다.

## 대안
- 파일 종류 아이콘을 기본으로: Finder와 비슷해 익숙하지만, 앱의 정체성이 가려진다. 사용자는 설정 옵션으로 두는 쪽을 골랐다.
- 실제 대상 파일 아이콘(`icon(forFile:)`): 타일마다 대상에 접근해야 하고, 대상 상태에 따라 아이콘이 바뀌어 연결 상태 표시와 섞인다.
- 색으로 고르는 용도: 색만으로 구분되고 연결 상태 색(빨강·주황)과 헷갈린다. 사용자는 모양으로 구분되는 배지를 골랐다.
- 배지와 색을 모두 고르기: 선택이 두 단계가 되고 화면이 요란해진다.
- 폴더 Bishop에 배지 두 개(F2): 아이콘만 봐도 폴더임을 알 수 있지만, 목록 크기(13pt)에서 미트라가 가려져 뭉개진다.

## 영향
- 기능 세션: W28은 아이콘 보기와 '파일 종류 아이콘' 설정을, W29는 용도 데이터(0021)와 고르는 곳을 구현한다.
  폴더 Bishop의 종류 문구는 W29에서 'Bishop · 폴더'로 바뀐다.
- 이력 원인 표(16.2)에 changePurpose → '아이콘 변경'을 더했다.
- 배지와 17·18장, 16.2 표에 쓴 SF Symbols는 모두 macOS 12 이하에서 도입되어 macOS 15에서 쓸 수 있다(CoreGlyphs `name_availability.plist`로 확인).
