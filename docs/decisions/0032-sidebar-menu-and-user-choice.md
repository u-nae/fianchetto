# 0032 사이드바 가리기/보기 메뉴와 자동 접기 중 사용자 선택

- 상태: 확정 (사용자 결정, 2026-10-06)
- 날짜: 2026-10-06

## 맥락
Board 사이드바는 툴바 버튼으로만 접을 수 있었고 보기 메뉴에 항목이 없었다(0018 '모든 명령은 메뉴로' 위반). 시스템 `SidebarCommands()`를 넣으면
보기 메뉴에 '사이드바 가리기/보기'(⌃⌘S)가 생기지만, 가상 머신(macOS 26.6.2)에서 제목이 상태와 관계없이 '사이드바 보기'로 고정되었다.
또 W17·W19는 이력 탭·비교가 자동으로 접은 사이드바를 닫을 때 '사용자 조작과 무관하게 열기 전 상태로' 돌렸다. 그래서 사용자가 방금 편 사이드바를
앱이 다시 접을 수 있었다.

## 결정
- 보기 메뉴에서 인스펙터 항목 바로 앞(시스템 사이드바 그룹 뒤 `CommandGroup(after: .sidebar)`의 맨 앞)에 앱 항목을 둔다. `.sidebar`를 replacing으로 바꾸면 그 앞에 붙인 보기 방식·탐색 그룹이 사라진다. 이름은 상태에 따라 '사이드바 가리기'/'사이드바 보기',
  단축키는 ⌃⌘S로 시스템과 같다. 툴바 버튼·이력 탭·비교와 같은 모델 값(`isSidebarVisible`)을 바꾸므로 접는 애니메이션(동작 줄이기 0.01초)도 같다.
  Board 목록이 보이는 화면에서만 켠다(저장소를 여는 중·복구 화면·목록 오류에서는 끈다). 디자인 세션 동의.
- (사용자 결정) 이력 탭이나 비교가 사이드바를 자동으로 접은 동안 사용자가 메뉴·⌃⌘S·툴바로 사이드바를 바꾸면, 닫을 때 되돌리지 않고
  사용자가 마지막으로 고른 상태를 지킨다. 사용자가 손대지 않았으면 지금처럼 처음 열기 전 상태로 돌린다.

## 대안
- 시스템 `SidebarCommands()` 그대로: 코드가 가장 적지만 제목이 실제 상태와 맞지 않는다.
- 자동 접기 규칙 유지(늘 열기 전 상태로): 예측하기 쉽지만 사용자가 방금 편 사이드바가 다시 접힌다.

## 영향
- W17 `W17-sidebar-collapse`·`W17-sidebar-already-collapsed`, W19 `W19-sidebar-collapse` 테스트의 기대값이 바뀌었다.
  DESIGN.md 16.1·19.1과 11.1(보기 메뉴)은 디자인 세션이 같은 규칙으로 고친다.
