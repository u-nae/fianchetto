# 0007 현재 구성은 현재 revision의 스냅샷이다(별도 Node 테이블 없음)

- 상태: 확정 (기준 문서 공백 해소, 에이전트 위임)
- 날짜: 2026-10-01

## 맥락
TECH_STACK "주요 개념"은 Node를 영구 개념으로 나열하고 "과거 revision이 현재의 수정 가능한 Node 모델을 그대로
참조하지 않도록 한다"고 적어, 현재 구성을 별도 Node 레코드로 저장하는 설계로 읽힌다. 한편 PRD §7과 TECH_STACK
"저장 방식"은 확정된 변경마다 전체 구성 스냅샷을 revision으로 저장한다. 두 가지를 함께 두면 현재 Node 레코드와 현재
revision 스냅샷이 같은 내용을 이중으로 가지며, 둘의 일치가 불변식 5(현재 구성과 revision은 함께 저장·함께 실패)의
추가 위험 지점이 된다. Project의 이름도 스냅샷의 프로젝트 이름과 이중이 된다.

## 결정
- 현재 구성은 `Project.currentRevisionID`가 가리키는 revision의 스냅샷이다. 영구 저장소에 수정 가능한 Node 레코드를 두지 않는다.
  Node는 스냅샷 안의 값(`ConfigurationNode`)으로만 존재한다.
- 구성 변경은 새 revision 추가와 `currentRevisionID` 이동을 한 저장 단위로 커밋한다. 성공 전에는 둘 다 바뀌지 않는다.
- 프로젝트 이름은 스냅샷에 있다. 목록·이력 표시를 위해 Revision에 그 시점의 프로젝트 이름을 불변 열로 함께 저장해,
  스냅샷 JSON을 디코딩하지 않고 목록을 만든다. Project에는 이름 열을 두지 않는다.
- ResourceReference(북마크·마지막 해석 경로)는 운영 정보라 수정 가능한 별도 레코드로 둔다(불변식 8, 0003).

## 대안
- 현재 Node 레코드 + revision 스냅샷: 편집 중 Node 단위 갱신이 가능하지만, 어차피 확정마다 전체 스냅샷을 만들므로 이점이 작고
  이중 상태의 일치를 매 저장마다 보장해야 한다.
- 현재 구성을 Project에 별도 JSON 열로 저장: 현재 revision 스냅샷과 같은 내용이 이중으로 남는다.

## 영향
- TECH_STACK "주요 개념"의 Project·Node·Revision 설명과 "데이터와 구성 이력" 문단을 이 결정에 맞게 갱신했다.
- 불변식 6(과거 구성이 현재의 수정 가능한 Node를 공유하지 않음)은 수정 가능한 Node 레코드가 없으므로 구조적으로 성립한다.
- 현재 구성을 표시하려면 현재 revision 스냅샷 하나를 디코딩한다. 비용은 W26 측정 대상이다.
