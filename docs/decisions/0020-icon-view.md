# 0020 구성 영역에 아이콘 보기를 더한다

- 상태: 확정 (사용자 결정, 2026-10-03)
- 날짜: 2026-10-03

## 맥락
TECH_STACK은 "기본 UI는 자유로운 캔버스 대신 계층형 목록으로 시작한다"고 정했다. 실제 앱을 쓰면서, Board·Wing으로 이미 나뉜
구성에서 한 Board의 항목이 아이콘으로 다 보이지 못할 만큼 많은 경우는 드물고, 3열 화면에서 트리 열이 좁아 보기 힘들다는 의견이 나왔다
(사용자). Finder처럼 목록 보기와 아이콘 보기를 모두 두자는 제안이다. 1단계로 오른쪽 열을 접을 수 있는 인스펙터로 바꿨다(#31).

## 결정
- 구성 영역에 목록(트리) 보기와 아이콘 보기를 둔다. 보기 메뉴 아이콘(⌘1)·목록(⌘2)과 툴바로 전환한다(Finder 관례).
- 아이콘 보기는 Finder처럼 한 번에 한 단계(최상위 또는 Wing 하나)를 보이고, Wing 이중 클릭·⌘↓로 들어가며 ⌘↑·경로 막대로 위로 간다.
  Bishop·웹 링크의 이중 클릭·⌘↓는 열기다.
- 두 보기는 같은 데이터(부모·형제 순서)를 보여 주는 방식일 뿐이다. 자유 좌표 배치를 저장하지 않고, 배치 변경은 기존 이동 규칙(W12)을 따른다.
- 보기 방식은 Board별 화면 설정으로 다시 실행해도 기억하고("Board별 보기, 위치는 세션만"), 아이콘 보기의 현재 위치와 뒤로 기록은 화면 세션 동안만 둔다.
  둘 다 revision을 만들지 않는다(사용자 결정, 명세 게이트 t-w28-5021855b Q-W28-1).
- 타일 기호는 디스크에 접근하지 않는다. 기록 당시 경로의 확장자로 정한 일반 아이콘은 허용하고, 실제 파일 아이콘은 쓰지 않는다
  (PRD §8 경량화, W15 확인 시점 규칙).
- 첫 버전 범위에 넣고, 작업 항목 W28로 W17보다 먼저 진행한다. 에이전트 권장안이며 사용자가 채택했다.

## 대안
- 인스펙터 접기만 한다: 넓어지지만 계층이 깊으면 여전히 트리를 펼쳐 내려가야 한다.
- 자유 배치 캔버스: TECH_STACK이 피한 방향이고, 위치를 저장하면 구성 이력의 의미가 바뀐다.
- 첫 버전 뒤로 미룬다: 이력 화면(W17·W18)이 한 가지 보기만 전제로 만들어져 나중에 다시 손봐야 한다.

## 영향

- 납품 범위(F01–F12)의 기능 목록은 바뀌지 않는다. F02·F03·F04의 화면 표현이 하나 늘어난다.
