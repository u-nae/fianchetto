# 0006 화면 용어: 프로젝트는 Board, 로컬 연결 항목은 Bishop

- 상태: 확정 (사용자 결정, 2026-10-01). 가상 그룹의 화면 용어는 [0017](0017-group-screen-term-wing.md)이 Wing으로 대체했다.
- 날짜: 2026-10-01

## 맥락
PRD §1은 비숍을 브랜드 모티프로만 쓰고 UI 용어는 프로젝트·그룹·연결을 쓰도록 정했다. 사용자가 제품명
Fianchetto에 맞춰 체스의 비숍을 컨셉의 중심으로 삼기로 했다. 최상위 단위는 Board, 그 안에서 로컬과 연결하는
항목은 Bishop으로 부르고, 생성 동작은 "create/new/add bishop" 같은 형태를 쓴다.

## 결정
- 화면에서 Project는 **Board**, 로컬 파일·폴더를 가리키는 연결 항목(Node `file`/`folder`)은 **Bishop**이라 부른다.
  Bishop은 비숍의 긴 대각선처럼 Board에서 디스크의 먼 위치까지 닿는 연결이다.
- 가상 그룹은 **그룹**, 웹 링크는 **웹 링크**로 유지한다. 둘 다 로컬과 연결되지 않으므로 Bishop이 아니다.
- 표기: 한국어 UI 문장 안에서 Board·Bishop을 영문 고유 용어로 쓴다.
  예: "Board 만들기", "새 Bishop", "Bishop 추가", "Bishop 제거", "연결 대상 변경".
- 체스 규칙(이동 규칙, 칸, 기물 상호작용)을 기능이나 화면 문구에 끌어오지 않는다. 사용자가 체스를 몰라도 쓸 수 있어야 한다.
- 코드·데이터 모델·내보내기 형식의 이름은 중립 용어(Project, Group, Node, ResourceReference)를 유지한다.
  화면 용어는 String Catalog에만 둔다. 이름을 바꿔도 데이터 형식이 바뀌지 않게 하려는 PRD §1 원칙을 따른다.

## 대안
- 가상 그룹을 Bishop으로: Bishop 자체는 로컬과 연결되지 않아 "로컬과 연결할" 성질과 맞지 않는다.
- 그룹과 연결 폴더를 하나로 합침: 연결 폴더가 하위 항목의 부모가 될 수 없다는 핵심 데이터 규칙을 뒤집는다.
- 한글 음차("보드", "비숍") 또는 UI 전체 영문: 사용자 선택에서 제외됐다.

## 영향
- PRD §1(이름과 용어), §5(핵심 개념), §8(UI 언어와 전달)을 갱신했다.
- `CLAUDE.md` "UI·문구"의 용어 목록을 갱신했다.
