# 0015 경고 0개 규칙에서 XCTest 내부 진단은 세지 않는다

- 상태: 확정 (사용자 결정, 2026-10-03)
- 날짜: 2026-10-03

## 맥락
`scripts/verify.sh`는 W01부터 Debug 테스트 로그와 Release 빌드 로그의 경고 0개를 요구한다. 2026-10-02 밤부터 W11 UI 테스트 실행 중
XCTest가 `<unknown>:0: warning: -[테스트] : [Internal] Thread running at User-interactive quality-of-service class waiting on a lower QoS
thread ...` 진단을 내기 시작했다. 모든 테스트는 통과했고, main에서도 재현되며, 화면을 켜도, 다른 세션의 빌드를 멈춰도 나왔다.
앱 코드나 컴파일러가 낸 경고가 아니라 테스트 러너 내부 진단이다. 그런데도 이 경고가 모든 PR의 전체 검증을 막고 Release 단계까지 가지 못하게 했다.

## 결정
경고 검사를 `scripts/check-warnings.sh`로 분리한다. 컴파일러 경고와 빌드 시스템 경고는 그대로 하나라도 있으면 실패한다.
`<unknown>:0: warning: -[테스트] : [Internal] ...` 형태의 XCTest 내부 진단만 세지 않고 "참고"로 따로 출력한다.
메인 스레드 검사처럼 테스트 이름이 붙은 다른 런타임 경고는 계속 실패로 센다. 에이전트 권장안이며 사용자가 채택했다.

## 대안
- 원인 조사 계속: XCTest 내부 동작이라 해결 여부가 불확실하고, 그동안 모든 PR의 전체 검증이 실패 상태로 남는다.
- 규칙 유지, 사람이 판단: Release 단계를 매번 따로 돌려야 하고 자동 검증의 의미가 약해진다.

## 영향
- 검증 출력에 "참고: XCTest 내부 진단 N개"가 보일 수 있다. 개수가 늘거나 문구가 바뀌면 원인을 다시 본다.
- 검사 스크립트 자체 테스트에 내부 진단만 있는 경우(통과), 일반 경고와 섞인 경우(실패), 다른 런타임 경고(실패)를 넣었다.
