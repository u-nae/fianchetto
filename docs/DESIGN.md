# Fianchetto 디자인 규칙 (초안)

> 상태: **초안**. 디자인 작업 세션이 이 문서를 출발점으로 쓰고, 확정한 항목은 `docs/decisions/NNNN-<slug>.md`에
> 기록한 뒤 이 문서를 같은 변경에서 갱신한다. 색 값·아이콘 모양처럼 "후보"로 적힌 것은 디자인 세션이 결정한다.
> 이 문서는 제품 동작(`PRD.md`)·기술 선택(`TECH_STACK.md`)·프로젝트 규칙(`CLAUDE.md`)을 바꾸지 않는다. 충돌하면 그쪽이 우선한다.

## 1. 원칙

1. **시스템 UI 위에 테마를 얹는다.** 목록·사이드바·툴바·시트·버튼·텍스트 필드·메뉴는 SwiftUI 기본 컨트롤을 그대로 쓴다.
   컨트롤을 직접 그리거나 창 테두리·제목 막대를 바꾸지 않는다. 사이드바 반투명, 키보드 포커스 링, 시스템 강조 색 설정,
   다크 모드, 고대비, 투명도 줄이기가 그대로 동작해야 한다.
2. **체스는 시각 톤으로만 쓴다(0006).** 색·질감·아이콘 모티프로 표현하고, 체스 규칙(말의 이동, 체크, 승패 등)을
   기능·문구·인터랙션에 끌어오지 않는다. 화면 용어는 Board·Bishop과 중립 용어만 쓴다.
3. **정보 영역은 조용하게, 정체성은 가장자리에.** 트리·상세 영역처럼 오래 읽는 곳은 시스템 기본에 가깝게 두고,
   테마는 앱 아이콘·강조 색·Bishop 심볼·빈 화면처럼 정해진 곳에 모은다.
4. **색만으로 구분하지 않는다(CLAUDE.md UI·문구).** 상태·과거/현재·오류는 항상 기호(SF Symbol)와 문구를 함께 쓴다.
   체스판의 흑백 대비를 상태 구분 수단으로 쓰지 않는다.
5. **macOS 15에서 동작해야 한다.** deployment target이 macOS 15.0이다. 더 새로운 OS 전용 API·재질(예: Liquid Glass 전용
   modifier)은 `if #available`로 감싸고, macOS 15에서의 모습을 기준으로 설계한다. 개발 기기(macOS 27) 화면만 보고 확정하지 않는다.

## 2. 테마를 표현하는 곳과 하지 않는 곳

| 영역 | 테마 표현 | 규칙 |
|---|---|---|
| 앱 아이콘 | **주 표현** | 비숍 실루엣, 피앙케토(긴 대각선) 모티프, 체스판 격자 등. 6장 참고 |
| 강조 색(AccentColor) | **주 표현** | 선택 표시·기본 버튼·포커스에 쓰인다. 3장 대비 기준을 지킨다 |
| Bishop 항목 심볼 | **주 표현** | 비숍 말 모양 커스텀 SF Symbol. 5장 참고 |
| 빈 화면(ContentUnavailableView) | 보조 | 두 색 체스판 일러스트(0016). 'Board 없음'·'구성 비어 있음'에서만 |
| Board 제목 머리 | 하지 않음 | 두지 않는다. 선택한 Board는 사이드바 선택으로 보인다(0016) |
| 상세 영역 배경 | 하지 않음 | 시스템 배경 그대로(0016) |
| 트리(목록) 행, 사이드바 | 하지 않음 | 시스템 목록 스타일·선택 색 그대로. 행 배경에 체스판 무늬 금지 |
| 메뉴·툴바·시트·알림 | 하지 않음 | 시스템 그대로. 문구만 String Catalog로 관리 |
| 상태 표시(W15) | 하지 않음 | 시스템 의미 색(`.red`, `.orange` 등) + 기호 + 문구. 7장 참고 |

## 3. 색

### 3.1 토큰 이름과 역할

Asset Catalog(`Fianchetto/Assets.xcassets`)의 Color Set으로 정의한다. 코드에 hex·RGB 값을 직접 쓰지 않는다.
빌드 설정 `ASSETCATALOG_COMPILER_GENERATE_SWIFT_ASSET_SYMBOL_EXTENSIONS = YES`가 이미 켜져 있어 `Color(.themeSurface)`처럼
생성된 심볼로 참조한다(문자열 이름 `Color("...")` 금지). 생성 심볼 이름: `.accent`, `.themeAccentText`, `.themeSurface`,
`.themeBoardGreen`, `.themeLine`.

| 토큰 | 역할 | 쓰는 곳 |
|---|---|---|
| `AccentColor` | 앱 강조 색(채움) | 전역 강조. 기본 버튼 채움(흰 글자 위), 선택 표시, 포커스 |
| `ThemeAccentText` | 강조 색의 글자·기호용 변형 | 배경 위에 강조 색으로 쓰는 글자·심볼(링크형 버튼, 강조 기호) |
| `ThemeSurface` | 테마 면 색(라이트=아이보리, 다크=에보니) | 지금은 어느 화면에도 쓰지 않는다(0016). 아이보리·에보니는 이 토큰의 두 값이며 따로 두지 않는다(0011) |
| `ThemeBoardGreen` | 보조 강조(체스판 녹색) | 일러스트·아이콘 보조 색. 글자 색으로 쓰지 않는다. 빈 화면 체스판에는 쓰지 않는다(0016) |
| `ThemeLine` | 장식 구분선·밝은 칸 | 빈 화면 체스판의 밝은 칸(0016). 목록 구분선은 시스템 것을 쓴다 |

글자·기본 배경·구분선·선택 배경은 **시스템 의미 색**을 쓴다: `.primary`, `.secondary`, `Color(nsColor: .windowBackgroundColor)`,
`.separator` 등. 테마 토큰으로 바꾸지 않는다.

### 3.2 팔레트 (0011 확정)

| 토큰 | 라이트 | 다크 | 라이트 고대비 | 다크 고대비 |
|---|---|---|---|---|
| `AccentColor` | `#8A5A2E` 월넛 | `#9D6634` | `#6B4624` | `#A16936` |
| `ThemeAccentText` | `#8A5A2E` | `#D2A06A` | `#6B4624` | `#E6C6A8` |
| `ThemeSurface` | `#F6F1E7` 아이보리 | `#2A2520` 에보니 | `#FFFFFF` | `#1E1E1E` |
| `ThemeBoardGreen` | `#3F6B4A` | `#8DB596` | `#2F5539` | `#B3D4BA` |
| `ThemeLine` | `#D9CDB8` | `#4A4037` | `#8C7A60` | `#9A8A74` |

대비(WCAG 상대 휘도 식, 배경은 개발 기기의 시스템 배경 `#FFFFFF`/`#1E1E1E`):

| 조합 | 라이트 | 다크 | 라이트 고대비 | 다크 고대비 |
|---|---|---|---|---|
| `AccentColor` 위 흰 글자 | 5.86 | 4.79 | 8.31 | 4.58 |
| `AccentColor` 대 배경(UI 요소) | 5.86 | 3.48 | 8.31 | 3.64 |
| `ThemeAccentText` 대 배경 | 5.86 | 7.13 | 8.31 | 10.33 |
| `ThemeAccentText` 대 `ThemeSurface` | 5.21 | 6.49 | — | — |
| `ThemeBoardGreen` 대 배경 | 6.15 | 7.29 | 8.47 | 10.35 |

- 채움용 `AccentColor`와 글자용 `ThemeAccentText`를 나눈다. macOS는 강조 색 채움 위에 흰 글자를 그린다. 다크 모드의 밝은 월넛
  (`#D2A06A`)은 어두운 배경 위 글자로는 좋지만(7.13:1) 흰 글자를 올리면 2.34:1로 부족하기 때문이다.
- `AccentColor` 다크 값은 흰 글자 4.5:1과 `#1E1E1E` 대비 3:1을 함께 만족하는 범위(상대 휘도 0.139–0.183)에서 골랐다.
  `#323232`처럼 더 밝은 배경 위에서는 3:1과 흰 글자 4.5:1을 동시에 만족하는 색이 없다(`#9D6634`는 2.68). 이 경우 흰 글자
  대비를 우선한다.
- 고대비에서 `ThemeSurface`는 시스템 배경 값으로 돌아가고, 나머지는 대비를 높인다.
- 고대비 값과 macOS 15에서의 실제 모습은 실기에서 Accessibility Inspector로 다시 잰다(W27).

### 3.3 대비·변형 기준

- 본문 글자 4.5:1 이상, 큰 글자(제목 18pt 이상 또는 14pt 굵게)와 UI 요소·기호 3:1 이상(WCAG 2.x AA).
- 모든 Color Set은 **Any(라이트)·Dark** 두 값과 **High Contrast** 변형을 둔다(Asset Catalog의 Appearances: Any, Dark +
  High Contrast 체크). 고대비 값은 대비를 더 높이거나 시스템 색에 가깝게 한다.
- 사용자가 시스템 설정에서 강조 색을 바꾸면 그 설정이 우선한다(macOS 기본 동작). 앱 강조 색은 "다중 색상"일 때만 보인다.
  이것을 막지 않는다.

## 4. 글자

- 기본은 시스템 서체(SF Pro)와 SwiftUI 텍스트 스타일(`.body`, `.headline`, `.caption` 등)이다. 크기를 pt로 고정하지 않는다.
- **세리프·둥근 글꼴은 쓰지 않는다(0016).** New York(세리프)은 한글에 대응하는 글꼴이 없어 명조 계열로 대체되고, SF Rounded는
  한글이 바뀌지 않아 라틴 글자만 달라진다. 빈 화면 제목도 시스템 서체를 쓴다. 외부 서체 파일은 넣지 않는다(외부 의존 0개, 라이선스 관리 회피).
- 숫자가 정렬돼야 하는 곳(포함 항목 수, 날짜 목록·이력 W17)은 `.monospacedDigit()`을 쓴다.
- 문구는 모두 String Catalog에 있다. 디자인 작업에서 문구를 바꾸면 `scripts/check-terms.sh` 금지 표현(DB·JSON·bookmark·북마크·
  파일 삭제)과 필수 용어 목록을 지킨다.

### 5.2 Bishop 커스텀 심볼 (0013 확정)

- 모양: 비숍의 머리(미트라)를 크게 그린다. 위에 구슬, 몸통에 대각선 홈(피앙케토의 긴 대각선), 아래에 받침띠가 있다.
  폴더 Bishop은 미트라를 줄이고 오른쪽 아래에 폴더 배지를 붙인다. 파일과 폴더는 색이 아닌 배지 모양으로 구분한다.
- 이름: `fianchetto.bishop`(파일), `fianchetto.bishop.folder`(폴더). 참조는 `Image(.fianchettoBishop)`, `Image(.fianchettoBishopFolder)`
  (생성 심볼). 문자열 이름 금지.
- 자산: `Fianchetto/Assets.xcassets`의 Symbol Image Set. 템플릿은 `scripts/design/generate-bishop-symbols.swift`가 만든다.
  24 격자의 선 디자인(선 굵기 1.6)을 채운 윤곽선으로 바꿔 넣는다. 모양을 고칠 때는 SVG를 직접 고치지 않고 스크립트를 고쳐 다시 만든다.
- 크기: 템플릿에는 Regular 굵기의 S·M·L 세 크기 글리프가 있다(SF Symbols 비율 0.783·1·1.29). 크기별 글리프가 없으면 그 크기를 요청하는
  곳에서 심볼이 비어 보인다. 툴바는 `.large`를 요청해서, M만 있을 때 'Bishop 추가' 버튼이 빈 원으로 보였다(2026-10-03에 S·L 추가로 고침).
- 한계: 굵기(weight) 보간은 없다. 굵기를 바꿔도 모양이 같다. 굵기 대응이 필요해지면 Ultralight·Black 기준 굵기를 같은 점 구조로 추가한다.
- 렌더링: 한 레이어(Monochrome)다. 색은 넣지 않고 사용처의 `foregroundStyle`을 따른다.

### 5.3 Board·Wing 커스텀 심볼 (0025 확정)

- `fianchetto.board`: 둥근 사각 윤곽선(반경 2.5) 안에 3×3 체스판의 다섯 칸을 채운다. 앱 아이콘(대각선 분할)과 빈 화면 체스판(0016)과 같은 줄기다.
  시스템 `square.grid.2x2`는 아이콘 보기 전환 버튼(17.1)에만 쓰고 Board에는 쓰지 않는다. 둘이 같은 모양이면 의미가 겹치기 때문이다.
- `fianchetto.wing`: `folder` 윤곽선 안에 대각으로 놓인 작은 칸 두 개를 넣는다. '담는다'는 느낌은 지키고, 실제 폴더(파일 종류 모드의 폴더 아이콘,
  폴더 Bishop)와 구분되는 가상 묶음임을 보여 준다.
- 위계: Bishop 미트라가 주인공이다. Board·Wing은 칸과 선만 쓰고 말 실루엣을 쓰지 않는다. 웹 링크(`link`)와 상태 기호는 시스템 기호를 유지한다.
  테마 기호는 Board·Wing·Bishop 세 가지에서 멈춘다.
- 제작: Bishop과 같은 생성 스크립트(`scripts/design/generate-bishop-symbols.swift`), 24 격자, 선 굵기 1.6, S·M·L 세 크기, 색 없는 단색 템플릿.
- 참조: `Image(.fianchettoBoard)`, `Image(.fianchettoWing)`. 목록·아이콘 보기는 `TileIcon.wing`으로 그린다. 툴바 'Wing 추가'도 Wing 심볼을 쓴다
  ('Bishop 추가'가 더하기 표시 없는 미트라인 것과 맞춘다).

## 6. 앱 아이콘 (0014 확정)

- 모티프: 월넛(왼쪽 위)과 아이보리(오른쪽 아래) 면을 긴 대각선으로 나누고, 가운데 미트라(Bishop 심볼과 같은 모양)의 색이
  양쪽에서 뒤바뀐다. 아이콘 안에 글자를 넣지 않는다. 색은 `AccentColor`·`ThemeSurface` 라이트 값과 같다.
- 자산: Asset Catalog의 `AppIcon` 세트(16–512pt, @1x/@2x). 앱 target 빌드 설정은 `ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon`이다.
  PNG는 `scripts/design/generate-app-icon.swift`가 만든다. 모양을 고칠 때는 PNG를 직접 고치지 않고 스크립트를 고쳐 다시 만든다.
- 모양: macOS 격자를 따른다(1024 캔버스, 본체 824, 여백 100, 모서리 반경 185, 아래쪽 그림자). macOS 15는 이 그림을 그대로 쓴다.
  개발 기기(macOS 27)는 같은 그림에 시스템 유리 효과와 모양 처리를 입혀 보여 준다.
- Icon Composer(`.icon`)는 아직 쓰지 않는다. 새 OS에서 밝기·색조 변형(다크·틴트 아이콘)이 필요해지면 같은 모티프로 `.icon`을 만들고,
  macOS 15용으로는 이 `AppIcon` 세트를 유지한다.

## 7. 상태 표현 (W15, 0010 확정)

W15에서 연결 상태를 트리에 표시한다. 상태 이름은 W14 안내 문구와 같다. 표현은 **기호 + 문구 + 시스템 의미 색** 셋을 함께 쓴다.
상태 기호는 행 앞의 종류 기호를 바꾸지 않는다. 이름 뒤에 문구와 함께 붙이는 배지로 쓰며, Bishop 종류와 관계없이 같다.

| 상태 | 문구 | 기호 | 기호 색 | 문구 색 |
|---|---|---|---|---|
| 정상 | (표시 없음) | — | — | — |
| 권한 필요 | 권한 필요 | `lock` | `.orange` | `.secondary` |
| 대상 없음 | 대상 없음 | `xmark.circle` | `.red` | `.secondary` |
| 볼륨 연결 필요 | 볼륨 연결 필요 | `externaldrive.badge.xmark` | `.orange` | `.secondary` |
| 확인 실패 | 확인 실패 | `questionmark.circle` | `.secondary` | `.secondary` |

- 확정 판정에는 ×를, 단정하지 않는 확인 실패에는 ?를 쓴다. 확인 실패에 일반 오류 기호(`exclamationmark.triangle`)를 쓰지 않는다.
- 기호 색은 보조 수단이다. 라이트 모드의 시스템 주황은 3:1에 못 미치므로(0010 측정) 문구에는 주황을 쓰지 않는다.
- VoiceOver 행 라벨에는 상태 문구를 넣는다. 정상 상태에서는 넣지 않는다.
- 값은 `Features/BoardBrowser/LinkStatusPresentation.swift` 한 곳에 둔다.
- 오류 항목도 트리에 남긴다. 행을 흐리게(투명도) 만드는 것만으로 표현하지 않는다.
- 과거 구성 보기(W18)는 "과거 구성" 띠 + 기호(`clock.arrow.circlepath`) + 문구로 현재와 구분한다. 배경 색만 바꾸지 않는다(16장).

## 8. 배치와 간격

- 창 구조(TECH_STACK UI 구성): `NavigationSplitView` 3단(Board 목록 · 구성 트리 · 상세). 최소 창 크기 820×480,
  Board 목록 열 min 200 / ideal 240. 크기를 바꿀 때 UI 테스트가 같은 창 크기에서 통과하는지 확인한다.
- 간격 단위: 4의 배수(4·8·12·16·20). 시트 내부 여백은 시스템 `.padding()`, 요소 사이 12.
- 시트 폭: 입력 360, 확인·목록 380–460. 내용에 맞춰 늘리되 화면 절반을 넘기지 않는다.
- 툴바·제목 막대는 시스템 스타일. 사용자 정의 배경을 넣지 않는다.

## 9. 빈 화면·일러스트 (0016 확정)

- `ContentUnavailableView`를 유지한다. 테마는 그 안의 이미지에만 쓰고, 제목·설명·버튼은 시스템 서체와 스타일 그대로 둔다.
- 일러스트: 'Board 없음'과 '구성 비어 있음'에 4×4 체스판(`Features/Shared/ChessboardIllustration.swift`, 72pt, 모서리 4)을 쓴다.
  밝은 칸은 `ThemeLine`, 어두운 칸은 `AccentColor` 두 색만 쓰고, 말·녹색·바탕 면 색은 넣지 않는다.
- 형식: 벡터 자산 대신 SwiftUI 코드로 그린다. 색 토큰을 그대로 쓰므로 다크·고대비 변형이 따로 필요 없고, 자산 파일과 생성 단계가 없다.
- 오류·안내 빈 화면('현재 구성을 읽지 못했습니다', '항목을 고르세요' 등)은 시스템 기호를 유지한다. 일러스트는 내용이 없을 뿐인 상태에만 쓴다.
- 일러스트에 글자를 넣지 않는다(현지화·접근성). 설명은 `Text`로 둔다.
- 장식 이미지는 VoiceOver에서 숨긴다(`.accessibilityHidden(true)`). 의미가 있는 이미지만 라벨을 준다.

## 10. 움직임

- 시스템 기본 전환(시트, 펼치기, 목록 갱신)을 쓴다. 장식 애니메이션을 넣지 않는다.
- 새 애니메이션을 넣으면 `@Environment(\.accessibilityReduceMotion)`일 때 끈다.

  키보드만으로 모든 명령 실행.

### 11.1 메뉴·키보드·오른쪽 클릭 (0018)

- **메뉴 꺼짐:** 지금 실행할 수 없는 메뉴 명령은 꺼서 흐리게 보인다. 판단은 모델의 `can…` 값으로 한다.
  'Board 만들기…'(⌘N)만 늘 켜 둔다. 앱 시작 때 저장소를 여는 동안 꺼짐이 굳으면 ⌘N이 동작하지 않았기 때문이다(W07).
  'Board 보관'과 '보관 해제'는 상황에 맞는 하나만 켜진다.
- **오른쪽 클릭 메뉴:** 메뉴 막대 명령의 일부를 같은 이름과 같은 순서로 보여 준다. 누른 항목을 먼저 고른 뒤 실행한다.
  - Bishop: 열기 / Finder에서 보기 / 다시 선택… / 연결 대상 변경… / 아이콘 ▸(W29, 18.4) / 이름 변경… / 이동… / 제거…
  - Wing: Bishop 추가… / Wing 추가… / 웹 링크 추가… / 이름 변경… / 이동… / 제거…
  - 웹 링크: 열기 / URL 변경… / 이름 변경… / 이동… / 제거…
  - Board 행: Board 이름 변경… / Board 보관 또는 보관 해제
  - 이력 탭 revision 행·'현재 구성' 행: 이 기록과 비교(W19). 메뉴 막대에 두지 않는 0018의 예외다(19.1, 0027).
  - 비교 화면의 행: 열기 / Finder에서 보기(19.6)
  - 아이콘 보기(17장)는 Finder 관례를 따른다. Wing 타일은 들어가기 / 이름 변경… / 이동… / 제거…이고 추가 명령을 두지 않는다.
    추가 명령(Bishop 추가… / Wing 추가… / 웹 링크 추가…)은 격자 빈 곳과 빈 Wing 화면의 오른쪽 클릭 메뉴에 두며, 지금 위치의 끝에 넣는다.
    Bishop·웹 링크 타일은 목록 보기와 같다.
- **Delete 키:** 트리에서 Delete(⌫·⌦)는 시스템 Delete 명령(`onDeleteCommand`)으로 '제거…' 확인 창을 연다. 편집 메뉴의 시스템 '삭제'
  항목 이름은 그대로 둔다. 앱이 만드는 문구는 모두 '제거'를 쓴다. 목록에 `onKeyPress`를 쓰지 않는다. 목록의 키보드 포커스를 가져가
  방향키와 펼치기까지 막는다.
- **드래그:** 놓을 수 있는 Wing 행과 빈 영역만 시스템 강조 색 테두리로 표시한다.
- **툴바:** 구성 열에 'Bishop 추가'와 'Wing 추가'를 둔다. 메뉴와 같은 명령이고 같은 조건에서 꺼진다.
- **보기 메뉴 순서:** 아이콘으로 보기·목록으로 보기 → (구분선) → 들어가기·상위 Wing으로·뒤로 → (구분선) → 사이드바 가리기/보기(⌃⌘S) →
  인스펙터 보기/가리기(⌥⌘I) → 이력 보기(⌘Y) → 현재 구성으로 돌아가기 → 현재와 비교 → 비교 닫기.
  앞뒤에 시스템 항목('탭 막대 보기'·'모든 탭 보기', '전체 화면 시작')이 붙는다. 탭 항목은 창이 `WindowGroup`이라 생기며, 단일 창 전환(점검 7번) 때 다시 본다.
- **사이드바 메뉴:** 시스템 `SidebarCommands()`는 macOS 26에서 제목이 '사이드바 보기'로 고정되어 쓰지 않는다. 같은 자리·같은 단축키(⌃⌘S)에
  앱 항목을 두고 이름을 상태에 따라 '사이드바 가리기'/'사이드바 보기'로 바꾼다. 툴바 버튼·이력 탭·비교와 같은 상태를 쓰고, Board 목록이
  보이는 화면에서만 켠다(저장소를 여는 중·복구 화면·목록 오류에서는 꺼짐). `.sidebar`를 replacing으로 바꾸면 앞에 붙인 보기 그룹이 사라지므로
  `CommandGroup(after: .sidebar)`의 맨 앞에 둔다(0032).
- **도움말 메뉴:** 도움말 문서가 생기기 전까지 기본 'Fianchetto 도움말' 항목을 뺀다.
- **검증:** XCUITest에서는 트리 목록이 키보드 포커스를 받지 못한다. 그래서 방향키와 Delete 키 동작은 실제 키보드로 수동 확인하고,
  메뉴 꺼짐과 단축키는 `NativeCommandUITests`로 확인한다.

## 12. 코드 구조

- 자산: `Fianchetto/Assets.xcassets`(0011에서 만듦). 소스 폴더가 폴더 동기화 그룹이라 폴더를 만들면
  target에 자동 포함된다. pbxproj의 파일 목록은 고치지 않는다.
- 빌드 설정(앱 target Debug·Release 모두): 강조 색을 쓰면 `ASSETCATALOG_COMPILER_GLOBAL_ACCENT_COLOR_NAME = AccentColor`,
  아이콘을 쓰면 `ASSETCATALOG_COMPILER_APPICON_NAME = <아이콘 이름>`. pbxproj를 직접 고치거나 Xcode에서 설정한다.
  `scripts/check-build-settings.sh`가 검사하는 값(Swift 6, strict concurrency, macOS 15.0, arm64)은 건드리지 않는다.
- 공용 스타일 코드: `Fianchetto/Features/Shared/`에 둔다(예: `Theme.swift`의 간격 상수, 빈 화면 공용 View, ViewModifier).

- View 파일에서는 스타일 부분만 바꾼다. 화면 상태 모델(`BoardBrowserModel`)·서비스·저장소는 디자인 작업에서 고치지 않는다.
  기능 작업(W15 이후)이 같은 View 파일을 계속 고치므로, 디자인 변경은 작게 나눠 자주 병합한다.
- 모든 화면은 Xcode Preview를 둔다: 라이트, 다크, 빈 상태, 긴 이름. 미리보기 데이터는 실제 저장소를 열지 않는 값으로 만든다.

## 16. 이력 화면 (W17·W18, 0019)

### 16.1 구조
- 오른쪽 열은 인스펙터(`.inspector`) 하나다. 보기 메뉴 '인스펙터 보기/가리기'(⌥⌘I)와 툴바 버튼(`sidebar.right`)으로 접고 편다.
  인스펙터 안의 맨 위에 '항목 | 이력' 세그먼트가 있어, 항목 상세와 이력을 같은 자리에서 전환한다. 오른쪽 열이 둘로 늘어나지 않는다.
- 툴바의 이력 버튼(`clock.arrow.circlepath`, 도움말 '이력')과 보기 메뉴의 '이력 보기'(⌘Y, Safari의 방문 기록과 같은 키)는
  인스펙터가 접혀 있으면 펴면서 이력 탭을 연다. 이력 탭에서 다시 누르면 항목 탭으로 돌아간다.
- 이력 탭을 열면 Board 사이드바를 접고(`NavigationSplitView` columnVisibility), 이력 탭을 닫으면 이전 상태로 돌린다. 가운데 구성 영역의 폭을 지키기 위해서다.
  자동으로 접힌 동안 사용자가 사이드바를 바꾸면(보기 메뉴 '사이드바 가리기/보기', ⌃⌘S, 툴바 버튼) 닫을 때 되돌리지 않고 그 선택을 지킨다(0032).
  앱이 접고 펼 때도 툴바의 사이드바 버튼처럼 애니메이션으로 바꾼다(SwiftUI 기본 애니메이션). 동작 줄이기에서는 0.01초로 사실상 즉시 바뀐다.
  애니메이션을 빼고 바로 바꾸면 macOS 26에서 분할 뷰 제약이 충돌하므로, 동작 줄이기에서도 같은 애니메이션 경로를 탄다(0029).
- 가운데 구성 영역은 revision을 고르면 그 자리에서 과거 구성으로 바뀐다. 목록 보기·아이콘 보기 등 보기 방식과 관계없이 같은 띠와 같은 읽기 전용 규칙을 따른다.

### 16.2 이력 탭
- 위에서부터: '날짜로 찾기'(날짜·시각 선택, 시스템 시간대), '현재 구성' 행, 날짜별 구역, 아래쪽에 '고른 항목' 카드.
- 날짜별 구역 머리글은 기록이 있는 날만 만든다: '오늘 · 10월 3일', '어제 · 10월 2일', '10월 1일', 다른 해는 '2025년 12월 30일'.
  기록이 없는 날을 빈 구역으로 보여 주지 않는다. 매일 스냅샷이 있는 것처럼 보이면 안 된다.
- 목록 순서는 revision 순번의 역순(최신이 위)이다. 필요한 만큼만 불러오고, 고른 revision만 디코딩한다.
- revision 행: 왼쪽 기호 + 원인 문구(본문), 아래 줄 '#순번 · 시각'(`.caption`, `.secondary`, `.monospacedDigit()`). 오른쪽에 체크포인트 수(`flag` + 숫자, W22에서 표시).
- 원인 문구와 기호(행에는 `RevisionSummary`만 쓰고, 차이 요약은 붙이지 않는다):

| cause | 문구 | 기호 |
|---|---|---|
| `created` | Board 만들기 | `plus.square` |
| `renameProject` | Board 이름 변경 | `pencil` |
| `addGroup` | Wing 추가 | `plus` |
| `addLinkedItems` | Bishop 추가 | `plus` |
| `addWebLink` | 웹 링크 추가 | `plus` |
| `renameNode` | 이름 변경 | `pencil` |
| `changeURL` | URL 변경 | `pencil` |
| `move` | 이동 | `arrow.up.and.down` |
| `remove` | 제거 | `minus` |
| `replaceTarget` | 연결 대상 변경 | `arrow.triangle.swap` |
| `restored(from:)` | #N에서 복원(출처 revision의 순번) | `arrow.uturn.backward` |
| `duplicated` | 과거 구성에서 만듦 | `plus.square.on.square` |
| `imported` | 가져오기 | `square.and.arrow.down` |
| `changePurpose`(W29) | 아이콘 변경 | `pencil` |

- 날짜로 찾기: 고른 시각 이하의 마지막 기록을 고르고 목록에서 그 행으로 이동한다. Board가 생기기 전이면 날짜 칸 아래에 '이 시점의 기록 없음'을 보여 주고 선택을 바꾸지 않는다.
- '고른 항목' 카드: 과거 구성에서 고른 항목의 이름, '당시 경로', '현재 위치'를 보여 준다. 둘이 다르면 '당시와 다른 위치'(`arrow.turn.down.right` + 문구)를 덧붙인다.
  '열기'·'Finder에서 보기'와 안내 '열면 지금의 파일이 열립니다. 파일 내용의 과거 버전은 보관하지 않습니다.'를 둔다. 웹 링크는 당시 URL을 보여 준다.

### 16.3 과거 구성 띠
- 가운데 영역 위, 보관된 Board 띠와 같은 `.quaternary` 바탕. 첫 줄: 기호 `clock.arrow.circlepath`(이력 버튼과 같은 기호, 7장) +
  '과거 구성 · 읽기 전용'(`.callout` 굵게)과 '현재로 돌아가기'.
  둘째 줄: '#순번 · 2026년 10월 3일 오후 2:20 기록'(실제 기록 시각)과 '현재와 비교', '이 구성으로…' 메뉴('복원…', '새 Board 만들기…').
- 단계별 진입점: W18 단계의 띠에는 둘째 줄의 기록 시각만 둔다. '현재와 비교'는 W19, '이 구성으로…'의 '복원…'은 W20, '새 Board 만들기…'는
  W21이 동작과 함께 더한다. 눌러도 아무 일이 없는 꺼진 버튼은 두지 않는다(0018 도움말 메뉴와 같은 기준).
- 보관된 Board에서는 '복원…'만 끈다. 조회·비교·새 Board 만들기는 켠다(0009).
- VoiceOver는 띠를 하나의 요소로 읽는다: '과거 구성, 읽기 전용, #12, 2026년 10월 3일 오후 2:20 기록'.
- 복원 확인 시트(W20, 0034): '이 구성으로…' 메뉴의 '복원…'은 복원 전용 시트를 연다. 제목은 '#n 구성으로 복원', 그 아래 한 줄에
  '현재 구성 → #n · 시각'(이전 = 현재 구성, 이후 = 복원 결과)을 적고, 요약은 0027 규칙('변화 N개 · Board 이름 변경')을 따른다.
  변경 목록은 항목마다 기호 + 이름과 19.3의 변화 문구에 '이전 → 이후' 값을 붙이며 한 요소로 읽힌다(Board 이름 변경은 Board 기호 행).
  순서 변경은 비교 화면의 설정과 관계없이 늘 센다. 현재와 같은 구성이면 '현재와 같은 구성입니다'와 '닫기'만 둔다. 아니면 기본 버튼
  '복원'(Return)과 '취소'(Esc)를 둔다. 같은 시트를 파일 메뉴 '이 구성으로 복원…'(0035, 단축키 없음)으로도 열 수 있다.

### 16.4 과거 모드의 동작
- 읽기 전용: 편집 메뉴 명령, 툴바의 추가 버튼, 드래그와 드롭, Delete 키는 꺼진다(모델의 `can…` 값이 거짓).
- 오른쪽 클릭 메뉴는 '열기', 'Finder에서 보기', '다시 선택…'(같은 대상의 접근 복구만, 0012)만 보여 준다. '연결 대상 변경…'은 두지 않는다.
- '현재로 돌아가기'는 띠 버튼, 이력 탭의 '현재 구성' 행, 보기 메뉴의 '현재 구성으로 돌아가기'로 할 수 있다. 앱을 다시 열면 현재 구성으로 시작한다.
- 과거와 현재를 색만으로 구분하지 않는다. 띠(기호+문구)가 기준이다.

### 16.5 식별자(제안)
- W17에서 구현된 `history-tab`, `history-toggle`(툴바 버튼), `revision-row-<순번>`, `date-lookup`은 11장 목록으로 옮겼다.
  W18에서 구현된 `past-banner`, `return-to-current`, `past-item-card`('고른 항목' 카드)도 11장 목록으로 옮겼다.

## 17. 아이콘 보기 (W28, 0020·0022)

### 17.1 전환
- 툴바 세그먼트 컨트롤 하나: `square.grid.2x2`(아이콘) | `list.bullet`(목록). 보기 메뉴 '아이콘으로 보기'(⌘1), '목록으로 보기'(⌘2). Finder와 같은 키다.
- 보기 방식은 Board마다 따로 기억하고, 다시 실행해도 유지한다(화면 설정, revision 없음, Q-W28-1). 처음 설치했을 때와 새 Board는 목록 보기다.
- 아이콘 보기의 현재 위치와 뒤로 기록은 화면 세션 동안만 둔다. Board를 바꾸거나 다시 실행하면 최상위에서 시작한다.
- 인스펙터(⌥⌘I)와 이력 탭(16장)은 두 보기에서 똑같이 동작한다.

### 17.2 격자와 타일
- `LazyVGrid`(적응형 열, 최소 104pt, 열 간격 12, 줄 간격 18), 바깥 여백 16. 순서는 구성 순서(왼쪽에서 오른쪽, 위에서 아래)다. 정렬 옵션은 두지 않는다.
- 타일 폭 104. 아이콘 영역 64×56(+4 여백). 기호 크기 40pt(SF Symbol은 `.light` 굵기, Bishop은 커스텀 심볼).
- 이름: `.callout`, 가운데 정렬, 최대 2줄, 넘치면 가운데 줄임(`.truncationMode(.middle)`, Finder처럼 확장자를 남김). 전체 이름은 도움말 풍선(`.help`)과 VoiceOver로 제공한다.
- 연결 상태(0010)가 정상이 아니면 아이콘 오른쪽 아래에 상태 기호 배지(바탕만큼 오려 낸 원)를 두고, 이름 아래 셋째 줄에 상태 문구(`.caption2`, `.secondary`)를 쓴다. 색만으로 알리지 않는다.

### 17.3 타일 기호
- 기본값(기호 타일): Wing은 `fianchetto.wing`(0025), 파일 Bishop은 Bishop 심볼(18장 용도 배지 포함), 폴더 Bishop은 Bishop 폴더 심볼, 웹 링크는 `link`. 목록 보기와 같은 기호를 크게 쓴다.
- 설정의 '파일 종류 아이콘'(18.4)을 켜면 Bishop만 확장자 기준 macOS 일반 아이콘 + Bishop 배지로 바뀐다. Wing·웹 링크는 그대로다.

### 17.4 선택·드롭
- 선택(한 개): 아이콘 영역에 둥근 사각형(반경 8) `.quaternary` 바탕. 이름에는 시스템 선택 색 알약(반경 4) 위에 흰 글자.
  창이 비활성이면 회색 선택 색(`unemphasizedSelectedContentBackgroundColor`)을 쓴다.
- 드롭: 놓을 수 있는 Wing 타일만 시스템 강조 색 테두리(2pt, 반경 8)로 표시한다(0018과 같은 규칙). Wing 타일 위에 놓으면 그 안으로 들어간다.
  빈 곳과 빈 Wing 화면에는 Finder에서 끌어온 파일·폴더만 받아 지금 위치의 끝에 넣는다. 같은 층의 타일을 빈 곳에 놓는 것은 받지 않는다(기록도 없음).
- 타일 사이에 끼워 넣는 순서 바꾸기는 첫 버전에 두지 않는다. 순서는 편집 메뉴의 위로·아래로 이동으로 바꾼다.
- 오른쪽 클릭 메뉴(Finder 관례):

| 누른 곳 | 메뉴 |
|---|---|
| Wing 타일 | 들어가기 / 이름 변경… / 이동… / 제거… |
| Bishop 타일 | 목록 보기와 같음(11.1) |
| 웹 링크 타일 | 목록 보기와 같음(11.1) |
| 격자 빈 곳, 빈 Wing 화면 | Bishop 추가… / Wing 추가… / 웹 링크 추가…(지금 위치의 끝, 보관된 Board·과거 구성에서는 꺼짐) |

  목록 보기의 Wing 행 오른쪽 클릭 추가는 그 Wing 안에 넣는다. 목록 보기에는 '지금 위치'가 없기 때문이다.

### 17.5 탐색과 경로 막대
- Wing 타일을 이중 클릭하거나 ⌘↓를 누르면 그 Wing 안으로 들어간다. Bishop·웹 링크에서 이중 클릭이나 ⌘↓는 열기(⌘O)와 같다.
- ⌘↑는 한 단계 위로 간다(최상위와 목록 보기에서는 꺼짐). 툴바 왼쪽에 뒤로 버튼(`chevron.left`, ⌘[)을 둔다.
- 메뉴 문구(보기 메뉴): '들어가기'(⌘↓), '상위 Wing으로'(⌘↑), '뒤로'(⌘[).
- 뒤로 기록에는 뒤로를 뺀 모든 위치 이동(들어가기, 상위로, 경로 막대 이동)을 쌓는다. 기록된 Wing이 없어졌으면 남아 있는 가장 가까운 상위로 간다.
- 아이콘 보기에서 추가(Wing 추가, 웹 링크 추가, Bishop 추가)는 선택과 상관없이 지금 위치의 끝에 넣는다(Finder의 새 폴더와 같은 관례).
  목록 보기는 기존 규칙(선택한 Wing 안, 아니면 선택 항목의 부모)을 따른다.
- 툴바 제목은 지금 보고 있는 Wing 이름, 부제는 Board 이름이다(최상위면 Board 이름만).
- 경로 막대: 아이콘 보기 아래쪽 24pt 띠(Finder의 경로 막대 위치). 'Board › Wing › …'을 기호와 함께 보여 주고, 각 칸을 누르면 그곳으로 간다.
  오른쪽 끝에 '항목 N개'(`.monospacedDigit()`). 목록 보기에는 두지 않는다(트리가 계층을 보여 준다).

### 17.6 빈 Wing
- `ContentUnavailableView` + 체스판 일러스트(0016, '내용이 없을 뿐인 상태'). 제목 'Wing이 비어 있습니다', 설명 'Bishop이나 웹 링크를 추가하거나 이곳으로 끌어 놓으세요.'

### 17.7 키보드·접근성
- 화살표 키로 격자 안 선택을 옮긴다(위·아래는 같은 열). 끝에서 반대쪽으로 넘어가지 않는다. 선택이 없을 때 누르면 첫 타일을 고른다.
  Return은 쓰지 않는다. Delete는 '제거…'(0018과 같은 시스템 명령).
- 연결 상태 확인(W15)은 타일을 고를 때(클릭·방향키) 그 Bishop만 한 번 한다. 탐색(들어가기·위로·뒤로)과 보기 전환은 확인하지 않는다.
- 목록에 `onKeyPress`를 쓰지 않는다는 0018 규칙처럼, 키 처리 방식은 실제 키보드로 포커스·방향키가 막히지 않는지 수동으로 확인한다.
- 타일 하나가 VoiceOver 요소 하나다. 라벨은 '이름, 종류, (상태), (용도)'. 식별자는 `icon-tile-<이름>`, 경로 막대는 `path-bar`.

### 17.8 과거 모드
- 과거 구성(16장)도 아이콘 보기로 볼 수 있다. 같은 띠, 같은 읽기 전용 규칙(편집·드래그·Delete 꺼짐, 오른쪽 클릭 메뉴 제한)을 따른다. Wing 안으로 들어가고 나오는 탐색과 경로 막대는 그대로 쓴다.

## 18. Bishop 용도 배지와 아이콘 설정 (W29, 0021·0022)

### 18.1 대상과 의미
- Bishop(파일·폴더)만 고를 수 있다. Wing은 `fianchetto.wing`, 웹 링크는 `link`로 고정한다.
- 용도는 구성의 일부다(0021). 바꾸면 revision이 생기고 이력에 '아이콘 변경'이 남으며, 과거 구성·복원·새 Board·내보내기에 따라간다.

### 18.2 배지 목록
| 저장 키 | 문구 | 배지 기호 |
|---|---|---|
| (없음) | 기본 | 배지 없음(파일), 폴더 배지(폴더) |
| `document` | 문서 | `doc.text.fill` |
| `data` | 데이터 | `tablecells.fill` |
| `image` | 이미지 | `photo.fill` |
| `code` | 코드 | `chevron.left.forwardslash.chevron.right` |
| `reference` | 참고 | `book.closed.fill` |
| `presentation` | 발표 | `play.rectangle.fill` |
| `todo` | 할 일 | `checklist` |
| `design` | 디자인 | `paintbrush.pointed.fill` |

- 저장 키는 바꾸지 않는다. 기호와 문구는 이 표만 고쳐서 바꿀 수 있다. 목록을 늘리는 것은 괜찮지만, 줄이면 기존 데이터를 따로 처리해야 한다.

### 18.3 합성
- Bishop 심볼(윤곽선) 위 오른쪽 아래에 배지 SF Symbol(`.semibold`, 아이콘 크기의 0.38배)을 겹친다. 배지 둘레 원(0.62배)만큼 Bishop 심볼을
  `.blendMode(.destinationOut)`으로 오려 내고 `.compositingGroup()`으로 묶는다. 선택 강조 바탕이 바뀌어도 오려 낸 자리가 어긋나지 않는다.
- 배지는 Bishop 심볼과 같은 `foregroundStyle`을 따른다(색을 따로 넣지 않는다). 목록 보기(13pt)와 아이콘 보기(40pt)에 같은 규칙을 쓴다.
- 배지 둘레 원은 칠하지 않는다. 투명하게 오려 낸 자리로 아래 바탕(창 바탕, 선택 행 색)이 보여야 한다. 그래서 다크 모드에서는 원이 어둡고
  배지가 밝게 보여 대비가 생긴다. 다크 모드에서 원이 밝게 채워져 보이면 합성이 잘못된 것이다. `compositingGroup()`이 빠졌거나,
  오프스크린 캐시(`cacheDisplay`) 렌더링의 한계일 수 있다(2026-10-03 디자인 시안에서 실제로 생겼고, `ImageRenderer`로 다시 그리니 정상이었다).
  구현 뒤에는 실제 앱 창에서 라이트·다크와 선택 행(강조 색, 비활성 회색)을 함께 확인한다.
- 폴더 Bishop(F1): 용도를 고르면 용도 배지가 폴더 배지 자리를 대신한다. 폴더라는 사실은 종류 문구 'Bishop · 폴더'와 인스펙터로 알린다.
  파일 Bishop의 종류 문구는 'Bishop'이다.

### 18.4 고르는 곳
- 세 곳에서 고른다(0018: 오른쪽 클릭 메뉴는 메뉴 막대 명령의 일부).
  - 메뉴 막대 편집 > '아이콘' 하위 메뉴
  - 인스펙터의 '아이콘' 선택(배지 기호와 문구가 함께 보이는 메뉴)
  - 오른쪽 클릭 메뉴의 '아이콘' 하위 메뉴
- 세 곳 모두 항목 순서는 18.2 표(기본, 문서 … 디자인)이고, 각 항목에 배지 기호와 문구를 함께 보인다. 지금 값에 체크 표시를 한다.
- 켜짐 조건도 세 곳이 같다: 편집할 수 있는 Board에서 Bishop을 골랐을 때. 보관된 Board, 과거 구성, Wing·웹 링크 선택에서는 꺼진다.
- 앱이 모르는 용도 키(새 버전이나 가져온 데이터에서 온 값)는 배지 없이 '기본'처럼 보이고, VoiceOver 라벨에 용도 문구를 붙이지 않는다.
  값은 그대로 보존한다. 고르는 곳의 값과 체크 표시는 '기본'이다(W29 명세 obligation W29-unknown-key-display).
  이때 '기본'을 고르면 화면은 그대로지만 키가 지워지고 revision이 남는다. 더 새 버전의 앱이 쓴 값에서만 생기는 드문 경우라 첫 버전은 이대로 둔다.

### 18.5 '파일 종류 아이콘' 설정
- 설정(Settings 장면) > 일반 > 'Bishop 아이콘': '기호(기본)' | '파일 종류 아이콘'. 화면 설정이라 revision을 만들지 않는다. 목록 보기와 아이콘 보기에 함께 적용한다(W28).
- '파일 종류 아이콘'이면 Bishop은 기록된 경로의 확장자로 정한 `UTType`의 macOS 일반 아이콘(`NSWorkspace.icon(for:)`, 디스크 접근 없음), 폴더는 일반 폴더 아이콘을 쓴다.
  오른쪽 아래에 작은 Bishop 배지를 붙인다. 배지는 반전 단색이다: 원은 `Color.primary`(라이트 짙은 원, 다크 흰 원),
  미트라는 `textBackgroundColor`이다. 원 지름은 아이콘의 0.42배, 미트라 여백은 원 지름의 0.18배, 원 둘레에 `textBackgroundColor` 테두리
  (size/40, 최소 0.5pt)를 두른다. 대비는 두 모드 모두 약 16:1이고, 시스템 강조 색 설정과 상관없다(강조 색 원은 그래파이트 강조 색의 다크 모드에서 2.80:1이었다).
  이 모드에서는 용도 배지를 아이콘에 그리지 않는다.
  용도는 인스펙터와 VoiceOver 라벨에 계속 보인다. 파일 종류가 이미 모양으로 드러나기 때문이다.
- 실제 대상 파일의 아이콘(`icon(forFile:)`)은 쓰지 않는다. 타일마다 대상에 접근해야 하고, 대상 상태에 따라 아이콘이 바뀌어 연결 상태 표시와 섞인다.

## 19. 구성 비교 화면 (W19, 0024·0027)

### 19.1 구조와 진입
- 비교는 가운데 구성 영역에서 그 자리에 열린다(16장의 과거 구성과 같은 자리). 비교 중에는 Board 사이드바를 접는다(16.1과 같은 규칙, 애니메이션 포함).
- 사이드바를 자동으로 접는 화면(이력 탭, 비교)이 하나라도 열려 있으면 접힌 상태를 유지하고, 마지막 하나가 닫힐 때 처음 열기 전 상태로 돌린다.
  이력 탭과 비교가 서로의 접기 상태를 덮어쓰지 않게 하기 위해서다. 그동안 사용자가 사이드바를 바꿨으면 되돌리지 않고 그 선택을 지킨다(16.1, 0032).
- 진입점:
  - 과거 구성 띠(16.3)의 '현재와 비교'. 기본 빠른 동작이다(PRD §6-E).
  - 이력 탭 revision 행과 '현재 구성' 행의 오른쪽 클릭 '이 기록과 비교'. 지금 보고 있는 구성(현재 또는 과거)과 비교한다.
    그 행이 지금 보는 구성과 같으면 꺼진다. 이력 목록은 한 행만 고르는 단일 선택을 유지한다.
  - 보기 메뉴의 '현재와 비교'('현재 구성으로 돌아가기' 아래). 과거 구성을 볼 때만 켜지고 비교 중에는 꺼진다. 띠 버튼과 같은 동작이다.
  - 비교 띠 안에서 양쪽 대상을 바꾼다(19.2).
- '이 기록과 비교'는 메뉴 막대에 두지 않는다. 0018의 의도된 예외다(0027). 이력 행을 고르면 그 행이 '지금 보는 구성'이 되므로,
  메뉴 막대에는 비교할 다른 대상이 없다. 키보드만으로는 행 고르기 → '현재와 비교' → 비교 띠 대상 메뉴로 같은 결과에 닿는다.
- 진입 명령('현재와 비교', '이 기록과 비교')은 순번이 작은 쪽을 이전, 큰 쪽(또는 현재 구성)을 이후로 둔다.
- 비교를 닫으면 연 곳(현재 구성 또는 그 과거 구성과 띠)과 원래 선택으로 돌아간다. 비교 화면의 선택은 현재·과거 선택과 따로 둔다.
- 비교 중에 이력 탭의 다른 revision 행이나 '현재 구성' 행을 고르면, 비교를 닫고 그 구성을 본다. 다른 Board로 바꿔도 비교를 닫는다.
  비교 대상은 비교 띠의 대상 메뉴로만 바꾼다.
- 비교는 목록(트리) 형태로만 보여 준다. 아이콘 보기(17장)에서 비교를 열면 그 비교 동안 목록 형태로 보여 주고, 비교를 닫으면 원래 보기로 돌아간다.
  이때 아이콘 보기의 현재 위치(보던 Wing)와 뒤로 기록도 그대로 돌아간다(세션 동안 유지, Q-W28-1).
- 보관된 Board에서도 비교할 수 있다(0009). 비교는 저장된 구성만 쓴다. 파일 시스템과 네트워크에 접근하지 않고, 연결 상태 확인(W15)도 하지 않는다.

### 19.2 비교 띠
- 가운데 영역 위, 과거 구성 띠와 같은 `.quaternary` 바탕. 비교 중에는 과거 구성 띠 대신 비교 띠만 보인다.
  첫 줄: 기호 `arrow.left.arrow.right` + '구성 비교'(`.callout` 굵게), 오른쪽에 보기 방식 세그먼트 '통합 | 나란히'(W19 ②),
  '순서 변경 표시'·'바뀐 항목만 보기' 체크상자, '비교 닫기'(기본 취소 동작이라 Esc로도 닫힌다, 19.6).
- 둘째 줄: 이전 대상 메뉴('#순번 · 기록 시각') → 이후 대상 메뉴('현재 구성' 또는 '#순번 · 기록 시각'), 오른쪽에 요약.
  대상 메뉴에는 '현재 구성'과 revision 목록(최신이 위)이 있다. 사용자가 고른 순서를 뒤바꾸지 않는다. 이전이 더 최근이면 거꾸로 본 변화가 보인다.
  새 대상을 읽는 동안에는 이전 대상과 결과를 그대로 두고, 읽기가 성공했을 때만 바꾼다.
- 요약(`.caption`, `.secondary`): '변화 N개'. N은 변화 표시가 붙는 항목 수이고, 제거된 Wing의 자손도 각각 센다. 접미는 ' · '로 잇는다.

| 경우 | 요약 |
|---|---|
| 기본 | 변화 3개 |
| Board 이름도 바뀜 | 변화 3개 · Board 이름 변경 |
| Board 이름만 바뀜(N=0) | Board 이름 변경 |
| 순서 변경을 숨김 | 변화 2개 · 순서 변경 1개 숨김 |
| 둘 다 | 변화 2개 · Board 이름 변경 · 순서 변경 1개 숨김 |
| 순서만 바뀌었고 숨김(N=0) | 변화 0개 · 순서 변경 1개 숨김 |
| Board 이름만 바뀌었고 순서도 숨김(N=0) | Board 이름 변경 · 순서 변경 1개 숨김 |
| 다른 revision인데 차이가 없음 | 변화 0개 |
| 두 대상이 같음 | (비움) |

- 보기 방식은 마지막 선택을 기억한다(화면 설정, revision 없음). 기본값은 '통합'이다. '순서 변경 표시'의 기본값은 켬이고, 이 값도 앱 전체로 기억한다.
  '바뀐 항목만 보기'는 비교를 열 때마다 꺼진 상태로 시작한다.

### 19.3 변화 표시
- 행 끝에 변화 종류를 기호 + 문구로 붙인다(`.caption`, `.secondary`). 색만으로 구분하지 않는다.
  한 항목에 여러 변화가 있으면 아래 표의 순서로 ' · '로 잇고, 기호는 첫 변화의 것을 쓴다(예: '이름 변경 · ‘개발’에서 이동 · 아이콘 변경').

| kind | 문구(통합 트리) | 기호 |
|---|---|---|
| `added` | 추가됨 | `plus.circle` |
| `removed` | 제거됨 | `minus.circle` |
| `renamed` | 이름 변경 | `pencil` |
| `moved` | ‘이전 위치’에서 이동 | `arrow.turn.down.right` |
| `reordered` | 순서 변경 | `arrow.up.arrow.down` |
| `targetReplaced` | 대상 교체 | `arrow.triangle.swap` |
| `urlChanged` | URL 변경 | `link` |
| `purposeChanged` | 아이콘 변경 | `paintbrush.pointed` |

- `moved`의 ‘이전 위치’는 바로 위 Wing 이름만 쓴다. 최상위에서 옮겼으면 ‘최상위’에서 이동이다. 전체 경로는 인스펙터 '변경 내용'에 둔다.
  부모가 바뀐 항목에는 `reordered`를 붙이지 않는다. 순서 변경은 두 구성에서 부모가 같은 형제끼리만 계산한다(W16).
- Board 이름이 바뀌었으면 트리 맨 위에 'Board 이름' 행(`fianchetto.board`, 0025, '이름 변경')을 둔다.
- 행 아이콘은 일반 트리 행(`NodeRow`)과 같게 `Label`의 아이콘 자리에 그려 목록의 강조 색을 받는다. 비교 화면에서 아이콘 색이 바뀌어 보이지 않게 한다.
- 제거된 항목의 행은 이름에 취소선을 긋고 '제거됨'(기호+문구)을 붙인다. 취소선만으로 알리지 않는다.
- '순서 변경 표시'를 끄면 `reordered`만 있는 항목은 변화 표시를 숨긴다(다른 변화와 겹치면 그 변화는 그대로 보인다). 요약 수에서도 뺀다.

### 19.4 통합 트리(기본)
- 이후 구성의 트리에 변화 표시를 붙인다. 제거된 항목은 이전 구성에서의 부모·순서 위치에 '제거됨' 행으로 끼워 넣는다.
  끼워 넣는 위치는 Domain 규칙이다(0027, 명세 결정표 removed_row_placement):

| 이전 부모 | 제거 행의 위치 |
|---|---|
| 최상위 | 최상위 |
| 이후에도 남아 있음(옮겨졌어도) | 그 부모의 이후 위치 아래 |
| 함께 제거됨 | 제거된 부모 행 아래에 중첩 |

  형제 사이에서는 이전 구성에서 바로 앞에 있던 형제 중 같은 부모 아래 남은 가장 가까운 것 바로 뒤에 두고, 없으면 맨 앞에 둔다.
  같은 기준점 뒤에 붙는 제거 형제끼리는 이전 구성의 순서를 지킨다. 제거된 Wing은 그 아래 자손도 모두 '제거됨'으로 중첩해 보인다.
- 펼침: 비교를 열 때와 대상·'순서 변경 표시'·'바뀐 항목만 보기'가 바뀔 때, 보이는 변화가 있는 행의 조상 Wing을 펼친다.
  변화가 접힌 Wing 안에 숨지 않게 하기 위해서다. 그 사이 사용자가 접은 Wing은 그대로 둔다.
- '바뀐 항목만 보기' 체크상자(기본 끔, 19.2): 켜면 변화가 있는 항목과 그 조상 경로만 남긴다.
- 인스펙터 '항목' 탭(비교 중):
  - 맨 위에 고른 항목의 기호와 이름(통합 트리의 표시 이름, 제거 항목은 당시 이름)을 머리글로 둔다. 'Board 이름' 행이면 Board 기호와 'Board 이름'이다.
  - 그 아래 '변경 내용' 구역: 이름, 위치, 대상, URL, 아이콘 중 바뀐 것만 '이전 → 이후'로 쓴다. 추가·제거 항목은 한쪽 값만 보인다.
    각 값은 라벨 아래 최대 두 줄, 가운데 줄임이다.
  - 위치 값은 최상위부터 직접 부모까지 Wing 이름을 ' › '로 잇는다(예: '문서 › 초안 → 최상위'). 17.5 경로 막대와 같은 구분자이고,
    Bishop의 파일 경로('/')와 구분된다(0027).
  - 고른 행이 없으면 '항목을 고르세요'(`sidebar.right`), 고른 행에 바뀐 값이 없으면 '바뀐 내용 없음'(`equal.circle`, 설명 없음)을 보인다.

### 19.5 나란히 두 트리
- 가운데 영역을 반으로 나눠 왼쪽에 이전 구성, 오른쪽에 이후 구성 트리를 두고 가운데에 구분선(`Divider`)을 둔다.
  각 열 위에 대상 이름('#9 · 2026년 10월 1일 오후 5:02', '현재 구성')을 `.caption` 굵게, `.secondary`로 쓴다.
- 'Board 이름' 행은 두 열 모두에 둔다. 각 열이 그 구성의 전체 트리이기 때문이다. 고르면 두 열에서 함께 강조한다.
- 두 트리 모두 표시 전용이다. 고른 항목은 양쪽에서 함께 강조하고, 고르면 반대쪽도 그 행으로 스크롤한다. 고른 항목의 조상은 양쪽에서 펼친다.
  스크롤을 늘 붙여 움직이는 동기화는 하지 않는다.
- 한쪽에만 있는 항목(추가·제거)을 고르면 반대쪽은 강조하지 않는다. 빈 자리를 따로 표시하지 않는다.
- 변화 표시 문구는 짧은 형태를 쓴다(이름, 이동, 대상, URL, 순서, 아이콘, 추가, 제거). 인스펙터의 '변경 내용'은 통합 트리와 같다.
- VoiceOver는 왼쪽 열을 다 읽은 뒤 오른쪽 열을 읽는다. 각 열은 '이전 구성'·'이후 구성' 그룹 라벨을 가진다.

### 19.6 동작과 빈 상태
- 비교 화면은 편집할 수 없다. 편집 메뉴 명령, 추가, 드래그, Delete는 꺼진다.
- 오른쪽 클릭 메뉴와 이중 클릭은 '열기', 'Finder에서 보기'만 둔다. 제거된 항목도 당시 참조로 열 수 있다(W18 과거 열기와 같은 규칙).
  메뉴 막대의 '열기'(⌘O)·'Finder에서 보기'(⌘R)도 비교에서 고른 행을 그 행이 속한 구성의 참조로 실행한다. 켜짐은 오른쪽 클릭 메뉴와 같다
  (Bishop은 둘 다, 웹 링크는 '열기'만, Wing·'Board 이름' 행·선택 없음은 꺼짐).
- 비교 중에는 '다시 선택…', '상태 새로고침', 아이콘 보기 탐색('들어가기', '상위 Wing으로', '뒤로'), '아이콘으로 보기'·'목록으로 보기'가 꺼진다.
  숨은 아이콘 보기 위치를 지키고, 연결 상태 확인을 하지 않기 위해서다. '현재 구성으로 돌아가기'는 비교를 닫고 현재 구성을 보인다.
- 빈 상태(`ContentUnavailableView`, 비교 띠 아래 남은 높이를 채운다):

| 경우 | 기호 | 제목 | 설명 |
|---|---|---|---|
| 두 대상이 같은 구성 | `equal.circle` | 같은 구성입니다 | 없음 |
| 다른 revision인데 차이가 없음 | `equal.circle` | 변화 없음 | 두 구성이 같습니다. |
| 거르기로 보일 행이 없음 | `line.3.horizontal.decrease.circle` | 표시할 변화 없음 | 순서 변경 표시를 켜면 순서만 바뀐 항목이 보입니다. |

  '변화 없음'은 실제로 차이가 하나도 없을 때만 쓴다. Board 이름만 바뀌었거나 순서 변경을 숨겨 표시할 변화가 0개가 된 경우는 두 구성이 같지 않으므로 쓰지 않는다.
  앞의 경우는 'Board 이름' 행을 보이고, 뒤의 경우는 트리를 그대로 보인다.
- 키보드: 비교 닫기는 Esc, '비교 닫기' 버튼, 보기 메뉴의 '비교 닫기'로 한다. Esc는 '비교 닫기' 버튼의 기본 취소 동작(`.cancelAction`)이라
  초점이 대상 메뉴나 트리에 있어도 닫힌다. 시트가 열려 있으면 시트의 Esc가 먼저다. 메뉴 막대 항목에는 Esc를 표시하지 않는다.
  방향키는 지금 초점이 있는 트리 안에서 움직인다.
- 식별자: W19 ①·②에서 구현된 것은 모두 11장 목록으로 옮겼다.
