# W20 과거 구성으로 복원 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 과거 구성 띠와 파일 메뉴의 '복원…'으로 차이 확인 시트를 열고, 확정하면 그 revision의 Board 이름·구성을 현재로 되돌리는 `restored` revision을 만든다.

**Architecture:** 판정은 서비스가 `ProjectStore` actor 안에서 한다(보관 → 대상 revision → 현재 구성 읽기 → 같음 여부, 결정표 `restore_request_outcome`). 시트 내용은 메모리에 있는 두 스냅샷에서 순수 값(`RestorePreview`)으로 만들고, W19와 변화 문구를 공유하려고 문구 부분만 `ChangeWording`으로 뽑는다. 화면 모델은 시트 상태와 확정 흐름만 맡는다.

**Tech Stack:** Swift 6(strict concurrency), SwiftUI, SwiftData, Swift Testing(단위), XCUITest(핵심 흐름 1개), `xcodebuild`.

**Spec:** `.spec-gate/runs/t-w20-f2dc76d0/spec-brief.md` (READY handoff `tdd-handoff.yaml`의 렌더. 명세 게이트가 brainstorming을 대신했다). 결정 기록 `docs/decisions/0034-restore-confirmation-sheet.md`, `0035-restore-in-file-menu.md`. 프로젝트 규칙은 `CLAUDE.md`.

- [ ] **Step 3: 구현**

  `ProjectStore.appendRevision`: `targetRevisionID`가 있으면 `decide` 전에 대상을 읽어 `ProjectState.restoreTarget`에 싣는다. `adapter.revisionSummary`가 nil → `.notFound`, 던지면 → `.unreadable`, `summary.projectID != projectID` → `.otherProject`, `adapter.snapshot(revisionID:)`이 던지면 → `.unreadable`, 아니면 `.found`. 기존 호출부는 기본값 nil로 그대로 동작한다.
