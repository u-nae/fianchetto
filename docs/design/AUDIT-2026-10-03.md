> 범위: `docs/design/REFERENCES.md` 4장의 1–3번(메뉴·키보드, 선택·드래그 피드백, 창 동작).
> 대상: main `4ecacdf`(W15·디자인 #17–#20 병합 시점). PR #23(빈 화면 체스판)은 들어 있지 않다.
> 방법: 두 가지로 확인했다. 결과 표의 '근거' 열에 어느 쪽인지 적었다.
> - 실행 확인: 개발 기기(macOS 27)에서 UI 테스트 전용 저장소로 앱을 띄우고, 임시 XCUITest로 메뉴 상태와 키 입력을 관찰했다.
>   임시 테스트는 커밋하지 않았고, 만든 데이터와 캡처는 지웠다.
> - 코드 확인: 소스만 읽고 판단했다. 실제 동작은 확인하지 않았다.

> 용어: 점검 당시 화면 명칭은 '그룹'이었다. 이후 화면 명칭이 Wing으로 바뀌어(0017), 권장안의 메뉴 이름은 Wing으로 적었다. 관찰 기록은 당시 명칭 그대로 둔다.

## 세부

### 1. 메뉴 항목이 늘 켜져 있다
- 관찰: Board가 하나도 없는 상태에서도 파일 메뉴의 '연결 대상 변경…', '열기', 'Finder에서 보기', 'Board 이름 변경…', 'Board 보관',
  '보관 해제'와 편집 메뉴의 '이름 변경…', 'URL 변경…', '위로/아래로 이동', '이동…', '제거…'가 모두 켜져 있다.
  'Board 보관'과 '보관 해제'도 동시에 켜져 있다. 누르면 아무 일도 일어나지 않는다.
- 원인: `BoardCommands`가 모든 항목을 켜 둔다. 앱 시작 시점에 ⌘N이 꺼진 채로 굳는 문제를 피하려던 것이다(주석).
- HIG 기준: 지금 실행할 수 없는 메뉴 명령은 흐리게 표시해, 사용자가 무엇을 할 수 있는지 메뉴만 보고 알게 한다.
- 권장: ⌘N 'Board 만들기…'만 예외로 켜 두고, 나머지는 모델 상태(선택한 항목의 종류, 보관 여부)에 따라 `disabled`로 끈다.
  '보관'과 '보관 해제'는 상황에 맞는 하나만 켠다. 메뉴는 열 때 상태를 다시 읽으므로, 메뉴를 열었을 때의 모습은 맞게 나온다.
  단축키로 실행하는 경우도 꺼진 항목이 실행되지 않는지 테스트로 확인해야 한다.

### 2. 접힌 그룹 안에 새 항목이 숨는다
- 관찰: 빈 Board에서 그룹 'Drafts'를 추가하면 Drafts가 선택된다. 이어서 그룹 'Data'를 추가하면 Data가 Drafts 안에 들어가는데,
  Drafts가 접혀 있어 트리에 보이지 않는다. Data는 선택된 상태지만 화면에는 없다.
- 원인: 선택한 항목이 그룹이면 그 안에 넣는 규칙(`insertionParent`)과 접힌 채 시작하는 `OutlineGroup`이 겹친다.
- 권장: 새 항목을 넣거나 옮긴 뒤에는 그 부모를 펼치고 새 항목이 보이게 스크롤한다. Finder도 접힌 폴더에 넣은 항목을 선택할 때 펼친다.
  어디에 넣을지 정하는 규칙 자체는 기능의 의미라 바꾸지 않는다.

### 3. 오른쪽 클릭 메뉴
- 관찰(코드): 구성 트리의 오른쪽 클릭 메뉴는 '열기'와 'Finder에서 보기'뿐이다. 그룹과 웹 링크에도 같은 두 항목이 나오고, Board 목록 행에는 오른쪽 클릭 메뉴가 없다.
  코드 주석은 "메뉴 막대와 같은 명령"이라고 하지만 실제로는 일부만 들어 있다.
- 권장: 항목 종류에 맞는 주요 명령을 넣는다. 메뉴 막대 명령의 일부를 그대로 쓰고 같은 순서·같은 이름을 쓴다.
  - Bishop: 열기 / Finder에서 보기 / 다시 선택… / 연결 대상 변경… / 이름 변경… / 이동… / 제거…
  - Wing: Wing 추가… / 웹 링크 추가… / 이름 변경… / 이동… / 제거…
  - 웹 링크: 열기 / URL 변경… / 이름 변경… / 이동… / 제거…
  - Board 행: Board 이름 변경… / Board 보관 또는 보관 해제

### 4. Delete 키
- 관찰: 항목을 고른 뒤에도 편집 메뉴의 '삭제'가 꺼져 있다. 코드에 Delete 키 처리(`onDeleteCommand`)가 없다.
- Mac 목록에서는 Delete 키로 고른 항목을 지우는 것이 관례다. 이 앱의 '제거'는 Board에서만 빼는 동작이고, 확인 창을 띄운다.
- 권장: 트리에 `.onDeleteCommand { model.beginRemove() }`를 붙인다. 그러면 Delete 키와 편집 > 삭제가 모두 '제거…' 확인 창을 연다.
  화면 문구에는 '삭제'를 쓰지 않는다는 규칙이 있다. 그래서 시스템 메뉴의 '삭제' 표기를 그대로 둘지는 따로 정해야 한다(아래 '사용자 확인 필요').

### 5. 드래그 피드백
- 관찰(코드): 행과 빈 영역의 `dropDestination`이 `isTargeted`를 쓰지 않는다. 그래서 끌고 있는 동안 어디에 놓일지 표시되지 않는다.
  목록 기본 동작으로 행이 강조되는지는 확인하지 못했다.
- 권장: 놓을 수 있는 행은 시스템 선택 강조와 같은 계열의 테두리로, 빈 영역은 영역 전체로 강조한다. 놓을 수 없는 곳에서는 강조하지 않는다.
  SwiftUI만으로 행 사이에 끼워 넣는 위치를 표시하기는 어렵다(REFERENCES.md의 SwiftUI 한계). 필요해지면 AppKit 보완을 검토한다.

### 6. 툴바
- 관찰: 툴바 버튼은 Board 목록의 '+'(Board 만들기) 하나다.
- 권장: 구성 열 툴바에 'Bishop 추가'와 'Wing 추가'를 SF Symbol 버튼으로 두고, 각 버튼에 `help`를 붙인다.
  메뉴와 같은 명령이고, 화면을 처음 보는 사용자가 주요 동작을 찾을 수 있게 하려는 것이다. 사용자가 툴바를 편집할 수 있게 할지는 나중에 정한다.

### 7. 창 개수
- 관찰(코드): `WindowGroup` 하나에 모델 하나를 함께 쓴다. ⌘N이 Board 만들기로 바뀌어 새 창 명령은 없다.
  하지만 창 메뉴에는 탭 관련 항목이 있어, 탭이나 두 번째 창이 생기면 두 창이 같은 선택 상태를 공유하게 된다.
- 권장: 첫 버전은 단일 창이므로 `Window` 장면(scene)으로 바꾸는 것을 검토한다. 사진·음악 같은 라이브러리형 앱과 같은 구조다.
  창 복원과 UI 테스트에 영향이 있는지 함께 확인해야 한다.

### 8. 도움말 메뉴
- 'Fianchetto 도움말'이 켜져 있지만 도움말 북이 없다. 시스템 기본 동작대로라면 누를 때 "도움말을 사용할 수 없습니다"가 뜬다(누르는 것은 확인하지 않았다).
- 권장: 첫 버전은 `CommandGroup(replacing: .help)`으로 항목을 빼거나, 저장소 README 같은 짧은 안내로 연결한다.

### 9. ⌥⌘N·⌥⌘L
- 관찰: UI 테스트의 키 합성으로 ⌥⌘N과 ⌥⌘L을 보냈을 때 시트가 열리지 않았다. 같은 명령을 메뉴로 실행하면 열린다. 기존 UI 테스트도 이 두 단축키는 쓰지 않는다.
- 결론: 사용자가 실제 키보드로 여러 번 확인했고 정상이다. 키 합성에서만 생기는 현상이다(⌥N은 미국식 자판에서 데드 키 ˜). 고치지 않는다.

## 사용자 확인 필요

- 2번은 사용자 요청으로 기능 세션이 고친다(`fix/expand-group-on-insert`: 넣거나 옮긴 항목의 부모 그룹과 상위 그룹을 펼침).
- 3·6번은 이미 메뉴에 있는 명령을 다른 위치에도 보여 주는 것이다. 새 기능은 아니지만, 화면 구성이 바뀐다.
- 4번에서 시스템 '편집 > 삭제'를 '제거…'와 연결하면 메뉴에 '삭제'라는 시스템 문구가 보인다. 이 앱은 '파일 삭제'처럼 원본을 지운다는
  인상을 주는 표현을 피한다. 그래서 키만 연결하고 메뉴 표기를 바꿀지, 그대로 둘지 정해야 한다.
- 7번은 창 구조를 바꾸므로 창 복원과 UI 테스트에 영향이 있다.
